# V10 第 22 轮备选 C：用 critic 的估计 PMI 作配准能量（只评估，不训练）

标签：PILOT/DEVELOPMENT。只读 CAL/DEV，没有读 TEST；DEV 只作描述，读过 DEV 后不做任何选择或改动。分支 `v10/r22-pmi-energy-20261022`（未推送）。

## 1. 设计

- 理论（`Variational_Cauchy_Schwarz_divergence.pdf` 式 (35)）：最优 critic T* = η = tanh(½ log p/q)，所以 PMI = 2·atanh(T*)。
- 同一 checkpoint、同一位姿搜索（3° 网格 × 4 px 平移盘，最好 3 个起点各 100 步 Adam，投影）、同一组 4096 个采样位置、同一扰动，只换能量：
  - **J**：原配准能量（各窗口自己的乘积参考；MF M0/M1 为精确 V 矩，MF perm1、MLP perm1、InfoNCE 为宿主的 1 个置换，MLP perm8 为 8 个置换）。
  - **PMI**：采样位置上 2·atanh(clip(T, −1+ε, 1−ε)) 的平均，ε = 1e−4 事先固定。MF：T = a(u)ᵀ W b(v)；MLP 和 InfoNCE：T = tanh f，atanh 还原 f（截断在 |f| ≈ 4.95）。
  - **EPT**：采样位置上 T 的平均（只保留 J 的正对一阶项）。这是第三个读出，用来区分“去掉参考项”和“atanh 变换”两个因素。它不是零成本：PMI 和 EPT 只算正对，单次配准比 J 快（L40S 上 MLP perm8 的 J 约 6 s，PMI/EPT 约 1.5 s），按已完成单元的配准时间，EPT 使配准耗时比只跑 J 和 PMI 多 32%（各单元在 19–47% 之间），占总配准时间的 24%。
- 单元：BF、EPFL × MF_VCS_M1 / M0 / perm1、MLP_VCS_perm1 / perm8、InfoNCE_host[J_perm1] × seed 1001–1003，共 36 个。checkpoint 就是各 final 历史 COMPLETE.json 里 CAL 选中的那个（`resolve_units.py`；本轮不做选择）。
- 每个单元一个作业：CAL 全部（BF 8 core × 10，EPFL 10 窗口 × 10）和 DEV 全部（BF 32 × 10，EPFL 74 × 10）。每个配准问题在同一个能量实例上依次用 J、PMI、EPT 各配准一次，所以三种能量的比较是同作业、同卡、同输入的配对比较；J 的重评同时与历史记录逐条对照，作为已知重评不确定性的参照。
- 指标：BF 用 err_full，<42 / <9，按配准合并（BF DEV32 口径）。EPFL 用 native px（= err_full/4），<10.5 / <2.25 px；CAL 按配准合并，DEV 按 72 个 scene unit 宏平均（中位误差取各 unit 中位数的中位数），与已有 EPFL 分析一致。

## 2. 实现与核查

- 接入点：`v10/r22_pmi/pmi_energy.py`。宿主的三类能量（`adapter.MFRigidEnergy`、`r6_reg_p2.RigidEnergy` 的 critic 类、`supplement.learned.MLPRigidEnergy`）都在 `j_critic(dv)` 里把候选位姿的移动侧描述子映射成能量；搜索只经 `batch()/grid_values()/value()` 调用它。`set_variant` 只替换单个能量实例上的 `j_critic`，类方法不动，J 路径就是原代码。T 的计算式与 J 的正对项逐字相同。
- 评估入口：`v10/r22_pmi/run_unit.py`。按 checkpoint 的 config 重建 Trainer（不读 FIT 图像），载入后核对模型哈希；J 路径分别沿用原评估器：BF 的 MF/MLP perm1 照 `scripts/v10_bf1/run.py` 的 evaluate，BF 的 MLP perm8/InfoNCE 用 supplement `RegistrationSession`，EPFL 用 `EPFLRegistrationSession`。23 个宿主数值文件按 sha256 锁定（与 pipeline、EPFL hw2 树逐字节相同；BF1 冻结源的 adapter 只多了训练相关的差异，配准路径相同）。冻结的 BF1/EPFL release 树没有改动。BF 用 DataGuard（TEST134 被拒），EPFL 用 stage-ACTIVATED 记录和冻结的 group record v2；读之前核对 data lock。每个作业实际只读了 CAL 和 DEV。
- CPU 检查（Slurm 1056092，cpu-high，合成编码器，不读数据）：全部 PASS，结果在 `results/CPU_CHECK.json`。
  - 五类宿主能量（MF moments / perm1、宿主 MLP critic、MLPRigidEnergy 1 / 8 置换）在 PMI、EPT 之间切换后回到 J，能量值、位姿梯度和网格值与未动过的实例逐位相同，`j_critic` 回到类方法；
  - PMI、EPT 与 float64 numpy 逐位置暴力计算一致（|差| ≤ 1.3e−8，T 逐位置 ≤ 3e−8）；T = ±1 时截断到 ±2·atanh(1−1e−4)，梯度为 0、有限；
  - float64 MF PMI 位姿梯度与中心差分一致（相对误差 5e−7）；
  - 经 `register_variants` 走原搜索器（CPU 缩小网格）得到的 J 记录与原 `registration_record` 逐位相同。
- GPU smoke（1056093 BF、1056094 EPFL，均在 RTX PRO 6000，每数据集 6 个家族 × seed 1001 × 5 次配准，CAL 2 + DEV 3）：
  - 所有路径都跑通，n_grid 60/60 一致；
  - 历史记录产自同型 GPU 的两个单元（EPFL M1、MLP perm8 seed 1001，原在 RTX），F_true 10/10 逐位相同，说明模型、输入和能量与原评估一致；
  - 历史记录产自 L40S 的单元，F_true 差到 fp32 卷积量级（|ΔF_true| ≤ 2.3e−4）；
  - J 的 err_full 逐位相同 1/60，|Δerr_full| ≤ 1.86，属已知的重评不确定性（位姿搜索不是确定性的）。
  - 披露：smoke 一开始的判据是“跨卡型 F_true 也在 T01 容差内”，这个判据太严，有 6/60 行不满足；之后改为同卡型逐位、n_grid 全部一致（commit 8ecf0509），没有改任何正式计算。
- 正式单元里每次 J 重评都与历史行逐条对照（`J_vs_stored`）：同卡型的单元 F_true 全部在 T01 容差内，例如 EPFL MLP perm8 s1002/s1003（L40S）740/740，BF M0 s1003（L40S）320/320；err_full 逐位相同的比例在 0–28% 之间。

## 4. 解读（描述性，开发证据）

**EPFL：critic 是 tanh(f) 形式时，PMI 能量让严格定位一致变好。** DEV <2.25 px，72 个 scene unit 宏平均，三族各 3/3 个 seed 为正，配对 bootstrap 区间都不含 0：

| 族 | PMI−J <2.25 px | 95% 区间 | unit 中位误差（px）J → PMI |
|---|---|---|---|
| InfoNCE_host | +3.98 | [+1.85, +6.53] | 0.865 → 0.496 |
| MLP perm8 | +2.64 | [+0.37, +5.42] | 0.718 → 0.595 |
| MLP perm1 | +2.18 | [+0.69, +4.07] | 0.744 → 0.513 |

- 逐配准翻转以失败→成功为主，如 InfoNCE 为 25/4、17/7、59/4。同一 checkpoint 用 J 重评，这些单元相对历史记录几乎没有翻转（0–2 次）。
- CAL 方向一致：三族 PMI−J 为 +4.0 到 +5.0 pp，3/3 个 seed 为正。
- 宽松阈值 <10.5 px 基本不变。
- 只看正对、不取 atanh 的 EPT 也有提高（+1.5 到 +3.0 pp），所以收益一部分来自去掉参考项，atanh 又多出约 1 pp。
- 参照：手工特征 MIND 在 EPFL 上的 unit 中位误差约 0.409 px。学习型 critic 用 PMI 读数后，从 0.72–0.87 降到 0.50–0.60。

**EPFL 的 MF 三族接近 0**：M1 +0.56、M0 +0.14、MF perm1 +0.19，区间都含 0。MF critic 是有界双线性形式 T=aᵀWb，不经过 tanh，所以 2·atanh(T) 并不还原 PMI；tanh(f) 形式的 critic 则 2·atanh(T)=2f，正是式 (35) 的 PMI 估计。

**BF：没有一致收益，宽松阈值上有代价。**
- 严格阈值 <9：MF perm1 为 +1.67 [+0.42, +3.12]（3/3）；MLP perm1 为 +0.94（3/3，区间含 0）；其余族接近 0。
- 宽松阈值 <42：MLP perm1 为 −3.02（三个 seed 都是 −2.8 到 −3.4）、InfoNCE −3.44、MLP perm8 −1.56，区间上限为 0。也就是说，PMI 能量在 BF 上多出一些大错配准。
- BF 的 <42 失败大多是能量本身偏好错误位姿（F_hat ≥ F_true），不是搜索没找到：J 128/163，PMI 155/183（前 9 个单元合计）。
- 一个可能的解释：atanh 会放大接近 ±1 的 T，少数位置可在错误位姿上主导能量。BF 图像中纹理稀疏的区域较多，更容易出现这种情况。这只是假设，本轮没有检验。

**合起来**：PMI 读数是一个与理论（式 35）一致、零训练成本的配准能量。在 EPFL 上，它对三种 tanh 形式的 critic 都稳定改善严格定位；在 BF 上没有改善，而且会增加大错。本轮只改读数，checkpoint 仍按 J 在 CAL 上选；C2 会检验"按 PMI 选 checkpoint、再按 PMI 评"的完整流程。结果都是 DEV 上的开发证据，不替换 V10 主结果，也不据此选模型。
