## 1 数据角色、协议与边界

- 角色由 manifest（sha256 `cc309cece34b`）重算：FIT 32、CAL 8、DEV 32，与 BF1 `DATA_LOCK.json` 的 72 个文件角色一致。BF1 协议记录：TEST134 `HOLD`、EPFL `NOT_ACTIVATED`、CONFIRM 0（BF1 冻结时的记录）；全部 BF 单元（含 RuLSIF_exact_v2 与容量扩展）的数据读取记录只含 FIT/CAL/DEV 的 manifest core（§2.3），没有读取 TEST 或 EPFL。EPFL 之后按其冻结协议单独运行；本文不读 EPFL 原始结果，EPFL 的数字只取自官方分析（§10）。本文不读任何 TEST 数据。
- 决定 §6.1 原文：
  > 当前维持 **FIT32、CAL8、DEV32**。DEV32 是开发主表。
  > 同时预登记一个保守敏感性分析：按 record_id 的下划线后部分作为 TMA 位置，排除与当前 FIT/CAL 同位的评估 core。跨 1B/2B 同位是否同一 specimen 尚未证实，此分组是敏感性假设。
  > DEV24 排除的 8 个 core：`1B_F4, 1B_H4, 1B_H9, 2B_D5, 2B_G3, 2B_G5, 2B_H2, 2B_I5`。
  > 统计以 core 为单位并在方法间配对；每个 core 的多个扰动不当作独立组织样本。另报告按 TMA 位置组重采样的保守敏感性。

  由 manifest 重算：FIT/CAL 共占 37 个 TMA 位置；DEV 中与之同位的 8 个 core（1B_F4, 1B_H4, 1B_H9, 2B_D5, 2B_G3, 2B_G5, 2B_H2, 2B_I5）与决定所列逐字相同，DEV24 保留 24 个，也与协议 P2 的 `tma_colocation_sensitivity` 一致。

  > 每族调参上限为**最多 9 个候选、最多 8 个 L40S 已分配 GPU 小时**，计入训练、checkpoint、CAL 配准及作业内开销；两者先到为准。排队时间另报。

## 4 以 core 为单位的配对差（描述性）

- 单位是 core。每个单元在每个 core 上汇总 10 个扰动：成功个数（<42、<9 px）与 10 个误差的中位数。方法的 core 得分是该方法全部主体单元（seeds 1001–1003；MI/NMI/MIND 为单一单元）的平均；两方法在相同的 core 与扰动上配对。
- 成功率差 = core 差值的平均（等于两方法 seed 平均成功率之差）；误差差 = core 差值的中位数（px）。差值一律为 A − B。
- 区间：core cluster bootstrap，10000 次、百分位 95%；TMA 位置组 bootstrap 按 record_id 下划线后的位置重采样。DEV32 的 32 个 core 分属 32 个位置组、DEV24 的 24 个分属 24 个，每组最多 1 个 core，所以两种重采样在同一随机流下给出逐位相同的区间（生成器检查）；对 DEV 而言，保守敏感性实际体现在 DEV24 的排除上。
- “按 seed”：两方法都有 1001–1003 时按相同 seed 配对的 3 个差值的范围；单一单元方法与对方每个 seed 比较。core 计数是 core 差值为正 / 负 / 零的个数。
- 参照组 A=MF_VCS_M1 沿用复现协议的比较范围（原文：“MF_VCS_M1 versus MF_VCS_M0, MF_VCS_perm1, MLP_VCS_perm1, MLP_VCS_perm8 and InfoNCE_host[J_perm1]”），另加 CoMIR/MI/NMI/MIND；机制组每行只改变一个因素（矩估计、critic 类、负参考个数、训练目标）。RuLSIF_exact（v1）与 RuLSIF_exact_v2（A1，硬件混合）都不进入配对。这些区间不是检验，不能读作优劣；必需基线集合尚未补齐。
