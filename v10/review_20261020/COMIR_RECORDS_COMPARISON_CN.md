## 读法

- 两边用同一份官方代码，训练长度相同，训练损失的量级也相近，看不出训练过程有明显差别。
- 已排除一项：V10 的配准评估是确定的，同一 checkpoint 重评逐位相同，所以 V10 的低分不是评估时的随机波动。
- 记录中能看到的唯一结构性差别，是 V9 的 `exclusion_radius_px = 128`。V10 是否有等价的采样规则，配置里没有记录，需要读代码确认。
- 原因仍未查明，旧的参照行不删除。

## 下一项最小核查（只读记录和代码，不训练）

1. 对照 V9 `cmd_comir` 与 V10 CoMIR_native 的 patch 采样代码，确认 V10 是否有 128 px 的排除半径或等价规则。
2. 找到 V9-G1 p1 的逐 core DEV 配准输出，确认它在 DEV 阶段、不是 TEST 阶段。然后用同一 DEV32 的 core 和扰动，逐 core 对比成功与否，看差距集中在哪些 core。
3. 对比 latent 生成：归一化、crop、几何、encode-then-register 的顺序。

只有确认是共享实现的错误，才按“新协议版本 + 受影响方法配对重跑”的规则处理。
