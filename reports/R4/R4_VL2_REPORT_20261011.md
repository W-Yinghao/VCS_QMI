## 2. Reading
- **The frozen wording stands as the protocol's text.**  Per the r5 package (docs/04 §2.1), the following **scientific correction is
  attached; the protocol is not edited:**
  - **C1 / C3a.**  An interval containing 0 only means it contains 0.  No equivalence or non-inferiority margin was fixed in advance, so these
    readings do not show that VCS(ν) equals softmax.  On RefCOCO+, with the same test-time detector information, softmax still leads (C3a).
  - **C3b.**  A non-significant C3b does not exclude a training effect, and it does not establish that all of the gain comes from fusion.  What
    the data show:
    - training VCS with the score reference (C2: +2.1 / +2.5) gains about as much as adding log s to the uniform VCS model at test time
      (+2.3 / +2.1);
    - the difference between the two is small and its interval contains 0.
- **What changes.**  Detector-score information is the main lever for the estimator objectives, about 2 points.  Whether it enters through
  the reference law in training or through test-time fusion makes no detectable difference here.  Softmax gains less from fusion (+0.6 / +0.7),
  so the VCS − softmax gap shrinks once both use the detector score.  It still favours softmax on RefCOCO+.
- **Not shown:** that changing ν improves the original QMI estimate.  A different ν defines a different Q, and J_ν is a different target.
- **Next (r5 R5-10):** a symmetric CAL-calibrated fusion weight for every fixed checkpoint (F1).  F2 (checkpoint selection) is not
  identifiable from saved states.
