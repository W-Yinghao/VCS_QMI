## 3. Reading
1. **The gap forms on the path from initialisation.**  With the same initial critic, batches and lr, direct VCS is behind direct JS at every
   readout up to the peak: posterior MSE 0.076 vs 0.063 at u500 and 0.050 vs 0.041 at u1000.  Both peak near update 1 000, and both overfit
   afterwards.
2. **From the same JS start, the fit criterion does not matter at the selected state (P1 ≈ 0).**  This is partly mechanical: CAL selection lands
   at or before the branch on seeds 1–2, where LV and LLc are the same state.  On the post-branch budget curve, continuing with J overfits faster
   than continuing with JS (+0.0059 at u2000).  The squared criterion is not better past the peak.
3. **P2 is a path effect, not a criterion effect.**  "JS start + J" beats direct VCS by 0.0077 only because its selected state is the JS path's
   state.  Per the fixed wording, the JS → J warm start is a solver path, not a new estimator, and it is not named.
4. **What this means for the VCS vs JS ordering on S (R4-01: JS ≥ VCS in 42 / 45 cells)** (hypothesis, this condition only):
   - Here the difference is an optimisation-path effect of the logistic vs the tanh-squared criterion from the same initialisation.
   - It is not a finite-sample advantage of J after a good start.
   - It is not a selection artefact: S2 holds at every fixed update, not only at the selected state.
