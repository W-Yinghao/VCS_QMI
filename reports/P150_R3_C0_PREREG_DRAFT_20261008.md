# Pre-registration — P150 (r3 R3-C0): one crossed diagnostic of detection (P143) vs estimation (P144) — DRAFT 2026-10-08

Source: r3 §10; P144 report (J at h ≤ 0 at n 3 000) vs P143 (colour 0.1 detected at h with power 0.60 for the same encoder).  CPU; frozen after the gate.

## 1. Cell
CIFAR-10 final VCS seed 1 (`P107_AP3_views4_800ep_seed1`), colour 0.1, sites h and O (frozen clean-h logistic head logits), plus the label-only null.
Features: the P143 store regenerated by `scripts/p109_i1_features.py --fp32-maps` (deterministic; the P143 stage-0 gate reproduced the recorded power
within 0.005) into `outputs/P150_features`.

## 2. Construction (P143's, seed 601 → the first draws coincide with P143 stage 0)
20 draws; per draw FIT / EVAL / POOL of n = 2 000 base images, fresh N | Y with p(N = 1 | Y) = 0.5 ± 0.3, planted features iff N = 1; B = 200 shared
within-class permutations of N on EVAL.  Per site, four critics on the same FIT draw: AUD-VCS (ridge-tanh two-stage on φ = [u(2N−1), 1], the P143
`vcs_closed`), AUD-JS (the P143 `js_exact`, logit u → T = tanh(u/2)), NEST-VCS and NEST-JS (the P144 Y-aware class, linear / MLP picked on VAL,
exact Q, 300 steps; 3 optimiser seeds, seed 0 reported, the other two give the refit spread).

## 3. One common readout on the same EVAL draw
Exact-Q common J: a₊(T(u_i, N_i)) + [(1 − p1_i) a₋(T(u_i, 0)) + p1_i a₋(T(u_i, 1))] per image; S_plugin; saturation; per-image contributions saved →
paired-by-image bootstrap (1 000 reps, shared indices across the four critics) for J and for every pairwise difference.  Detection as in P143: each
critic's own statistic with the shared permutations (rejection at α 0.05) and its rejection rate over the 20 draws.  Also the sampled-Q J of the audit
class (its original readout) and the fraction of NEST fits selecting step 0.

## 4. Pre-stated reading
The unit answers *why* the same features give detection without an estimable J: (a) if the exact-Q J of every critic is within its bootstrap interval of
0 while the permutation rejection rate stays near 0.6 at h, the condition **supports detection only** (the statistic exceeds its own null by far less
than the J scale resolves); (b) if the audit-class J is clearly positive and the nested-class J is not, the P144 reading was function-class-limited; (c)
if both are positive at h and near 0 at O, h → O loses the attribute dependence quantitatively.  No bug is presumed; no critic is extended beyond the
registered classes; the P144 result is not rewritten.

## 5. Cost
≈ 1 min per draw (two sites × four critics, 300-step nested fits, 200 permutations) → ≈ 30 min CPU, plus ≈ 4 min feature regeneration.
