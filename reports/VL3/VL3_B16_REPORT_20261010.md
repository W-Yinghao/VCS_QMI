## 2. Frozen readings
1. **Same posterior (VCS − JS):** close in every cell (three-seed intervals all contain 0; means −0.14 to +0.30).
2. **Estimator objective vs task loss:** after full fine-tuning **VCS reaches the ranking accuracy of candidate softmax** in every cell (within
   ±0.9).  Only one interval excludes 0, and it favours VCS (RefCOCOg × CLIP); the others contain 0, and the two seed-0 cells have softmax ahead by
   0.6.  This reverses the frozen-feature picture, where softmax led in all 30 cells (VL1 / VL2).  Wording: "fine-tuned end to end, VCS matches
   the task-matched softmax on grounding accuracy".  Not "VCS beats softmax".
3. **Estimator view:** encoders fine-tuned with VCS or JS expose **21–43 % more critic-fittable dependence** (J_recal) than encoders fine-tuned with
   softmax, in all six cells, at equal ranking accuracy.  Softmax's own critic is uncalibrated (J_own ≤ 0), as expected for a ranking loss.
4. **Fine-tuning value:** every objective gains +7 to +21 over its frozen-feature critic.  The gain is largest on RefCOCO (dense same-category
   scenes) and larger for the estimator objectives than for softmax.

## 3. Caveats
- One shared recipe, not tuned per objective (the mature task baseline keeps the same recipe as ours; no per-objective search).  CAL-Top-1
  selection for all.  DEV is a development split; official val / test untouched.
- VCS / JS often select late epochs (6–10) on CLIP, so a longer schedule might change the CLIP cells; not tested (would be a new pre-registered unit).
- Large backbones (VL3 add. 1, running) test whether the picture holds at scale.
