## 5. R5-30 code status and budget
- **Loss.**  `distribution_softmax` = −Σ p log softmax_r(2f) over all real proposals.  It matches the r5 reference in value and gradient
  (1e-12).  The R4-VL1 `set_softmax` also matches the reference's set softmax.
- **Checks passed (21 / 21 with the R4 law tests):**
  - one valid box: distribution = set softmax, in value and gradient;
  - the D2 identity L_D − L_E = log k + KL;
  - never-positive real proposals stay in the denominator;
  - padding values and extra padding change nothing, and padding gets zero gradient;
  - extreme logits are finite;
  - empty queries give zero gradient;
  - per-image weighting and exact chunk accumulation hold.
- **Recipe:** identical to R4-VL1 option A (inherited code, not YAML comments):
  - SigLIP 2 B/16 from the original pretrained weights, both towers;
  - AdamW 1e-5 / wd 0.05, 200 warm-up steps, cosine schedule, 10 epochs, 32 images per step;
  - critic init (10, −2.5); logits 2f;
  - exact chunk accumulation;
  - CAL all-proposal selection (ties → earliest epoch);
  - DEV at step 0 (gate) and once at selection.
- **Budget** (from the 18 R4-VL1 runs with the same recipe and the same loss cost):
  - about 74 min per run on RTX 6000 Pro / H100, 2.4–3.9 h on L40S;
  - 6 runs ≈ 8–20 GPU-hours, about 2–4 h wall time on the current quota.
  - The smoke (1034130) verifies the end-to-end code path and timing.
