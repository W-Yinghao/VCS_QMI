范围：package docs/04 §D03、docs/05 §2/§4/§5。生成脚本为 `scripts/v81/d03_scale_selection.py`，最终输出由 CPU 作业 1042243 生成（exit 0）。表格由 `results/d03_tables.md` 原样复制，正文数字由 `scripts/v81/d02_d04a_report_numbers.py verify` 核对。区间均为 prompt_group cluster bootstrap（2000 次，seed 2718），属于开发区间，不给 p 值。

## 0. 输入、定义与实现说明

- **输入**：与 V81_02 相同，即 24 个正式单元在 DEV、CAL_SELECT、CAL_PROB 上的导出，24 个 TUNE 单元在 DEV 上的导出，以及 DEV 上的 V7 单元、外部系统和核桥。标签只来自开发角色。
- **主读数**：prompt 宏平均，即每个 prompt 一票，prompt 内图像等权。V8-03 的 natural weight（uniform prompt → uniform image）对图像级量与 prompt 宏平均相同：本轮值与 V8-04 JSON 的 `mean_mse_natural` 差不超过 2e-16。image-micro 另列。
- **分解**（docs/05 §2，精确恒等式）：每池 MSE = b² + within。对池取平均后，b² 的平均又等于全局偏移的平方加上 prompt 间偏移的方差。两个恒等式的残差都在 1e-15 以下（`identity_residual*`）。
- **人工均值取精确的 sum(votes)/n。** package 参考实现会把 human_mean 重算为 hist·levels。等值但投票模式不同的图像之间可能因此相差 1 ulp，而且结果随 CPU/BLAS 的求和顺序变化。后果是 DEV 上 2855 个精确同分 pair 中有约 80–100 个被当作有信息 pair，使 pooled pair accuracy 偏低 0.0011–0.0014；`*_pkg_hist_mean` 列保留了 package 值。
- **精确版本的两项核对**：
  - 它与独立的 V7C-40 DEV 评分器一致到 5e-7（20 个系统的 pooled Spearman 与 pooled pair accuracy；package 值与之差到 0.0015）。
  - 导出的 CAL_SELECT 预测逐单元复现了训练日志中选中 epoch 的记录（MSE 与 pairwise 的差不超过 2.2e-16）。因此导出确实来自被选中的 checkpoint。
- **MSE 的适用范围**：1–5 MSE 只对 rating_mean 系统计算。VQAScore、TIFA、DSG、HPS、PN-VQA、CLIPScore 的 MSE 记为 NA（docs/04 §D03）。
- **交叉核对**：逐池的 MSE、regret、选中质量与 package diagnose 的 per_pool 一致（最大差 2.2e-15）。DEV/CAL_PROB 的 prompt 宏平均 MSE 与冻结的 V8-04 评价 JSON 一致（最大差 1.1e-16）。

## 1. [已知证据]

- docs/05 §2：MSE_pool = b² + within 是精确的代数恒等式。within 不是排名指标，正的线性尺度误差会增大它而不改变排序，所以必须与 pairwise、regret 并列报告。
- V8-03 冻结选模：每个单元按 CAL_SELECT 的 prompt 宏平均 mean-rating MSE 选 epoch（平局取较早者），lr 在 seed 17 上按同一准则选。DEV 与 GenAI 从不用于选择。
- docs/03 §2：epoch 索引 0 是第一轮训练完成后的模型，不是 pre-update 初始化，`best_e0` 的意思是“一轮后被选中”。逐 epoch 权重没有保存，只有 best/resume（docs/03 §3；V81_01）。

- CAL_SELECT 上所有臂的全局偏移都为正（+0.025 到 +0.159），DEV 上接近 0。这说明 CAL_SELECT 与 DEV 之间存在少量刻度漂移，各臂的方向相同。

## 3. [解释]

1. **H-A，只有刻度变化。**
   - 对六个刻度臂，全局刻度不是问题：全局偏移约为 0，仿射修复只在千分位上改变 MSE。MSE 约 30% 来自 prompt 间偏移，约 70% 来自同池中心化误差。
   - pair accuracy 与选图几乎不随损失变化。因此“总分相近”并不是刻度差异被平均掉的结果，而是各臂在同池区分上受到同样的限制：pair accuracy 约 0.70，暴露过 DEV 的 B0 为 0.79。
   - 对 U-RANK，刻度失真是真实的，仿射修复把它的 MSE 从 0.5633 降到 0.4855。但它的同池排序与其他臂相同，属于 docs/02 §3 第四行“排序与回归目标分歧”的情形，不说明排序臂成功。
2. **H-B，选模指标错位。**
   - 日志级证据弱：MSE 与 pairwise 两种准则在样本内最多只差 0.0075，而且在刻度臂之间，选模分数不预测 DEV 排序。
   - e0 模式是一个提示。CAL_SELECT MSE 在第一轮后就开始上升的单元多为 seed 1，它们在 DEV 上也较差。这有两种读法：一是该 seed 的训练本身较差，选模正确地取了最不差的 epoch；二是选模选得过早。没有逐 epoch 权重就无法区分，所以 C2 的前提“权重齐全”不满足。
3. **与其他系统相比。** 同一 FGA-BLIP2 骨干的 V7 单元（N0/M0/M1/M2）与 V8 各臂在 DEV 上没有可检测的差异，领域内明显更好的只有暴露的 B0。未训练的 VQA 类评分器和核桥在 DEV 上明显落后；这些都是领域内比较。
4. **主要改进余地不在刻度或损失形式，而在同池区分能力本身。** 这一判断与 V81_02 的决策一致性结论相同。它是指向 C1/C3 的开发证据，不是批准。

## 4. [未验证假设]

- 同池区分的瓶颈是视觉输入或适配范围（H-C/H-D），还是 3 票标注噪声带来的上限，本节无法区分。投票没有标注者 ID，因此无法做分半信度。
- e0 模式是 seed 效应还是选模效应，需要逐 epoch 权重才能判断，而这些权重没有保存。
- 仿射修复只是 CAL_PROB 上的次级分析，不替换主结果，也不作为改进方法导出（docs/04 §D03）。
