Rule (docs/04 D07): the external main table stays as published; every row shows its host, its training data and its route status so that a host
advantage is never attributed to the fitted loss; TIFA is the official route and DSG a local adaptation; the Table C kernel routes use the

  (n.s.), TIFA 0.262 (+0.312, Holm 0.0008), DSG 0.381 (+0.193, Holm 0.0008); pairwise preference +0.044 over VQAScore (Holm 0.0008).  U-CS − U-BCE

- **EvalMuse DEV (descriptive, V7C secondary; in-distribution).**  The EvalMuse-trained systems are far ahead of every external system (V7 arms

- **Table C kernel routes** (untrained BLIP-2 features + Nyström / RuLSIF / KDE bridges): CAL_PROB / DEV RPS 0.121–0.167 and mean-MSE 0.48–1.05

## 2. Cost (historical job timings; not a standard workload)

- V8 arm, one unit = 5 epochs × 2,379 grouped steps + 5 CAL_SELECT evaluations: 33–53 min (RTX PRO 6000), 34 min (H100 NVL), 63–71 min (L40S);
  peak training memory 7.8 GB; export (single BLIP-2 forward, batch 32, 364 px, fp16) 10–37 images / s depending on the GPU and the NFS state
  of the job — the 51-min outlier (U-CS-s1 on H100) is in the data and not explained by the log.
- External scorers on the 14,400 GenAI-Rank images (V7C-03): VQAScore 39 min on one L40S; TIFA questions 3.5 h + VQA 2.3 h on L40S; DSG generation
  ≈ 2.5 GPU-h + VQA ≈ 2.4 GPU-h.  Released FGA: native eval in the V7 N0 harness, not timed separately (`not_recorded`).
- These are the only comparable timings on record; the package's standard-batch measurement (same device, warm-up, fixed batch / resolution /
  prompt length, whole-image and pool totals, peak memory) is run once by D06 on the real GPU for the V8 host and recorded in V81_05.  No new
  external method is timed, and idle GPUs are not a reason to add one.
