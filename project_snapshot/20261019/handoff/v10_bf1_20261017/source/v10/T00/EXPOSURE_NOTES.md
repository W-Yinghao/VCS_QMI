## 2. Manifest conventions (`V10_DATA_MANIFEST.csv`)

- `dataset` BF_SHG / EPFL_RGB_NIR (names of `configs/V10_PROTOCOL.json`); `record_id` = core id (BF–SHG) or `<category>/<id>` (EPFL); `group_id` = the R6/V9 independent unit: the core, or the REG-P3 scene unit (near-duplicates merged; 8 merged units: country/0001+country/0025+country/0032, country/0016+country/0044, country/0023+country/0027, country/0036+country/0045, field/0011+field/0042, field/0013+field/0014, field/0020+field/0038, mountain/0039+mountain/0041).
- `fixed_path` = reference (BF; RGB), `moving_path` = moving image (SHG; NIR), as in REG-P1 / REG-P3.  Relative paths resolve against the data root `/projects/EEG-foundation-model/yinghao/data`; the held test rows give V9-G1's absolute extracted-copy paths.
- `role` = V10 role = the R6/V9 role.  Rows excluded from every role (the 57 EPFL exclusions) have an empty role.  The 134 BF–SHG test cores carry `role=DEV` (their only admissible V10 role: development / repeat benchmark) with `inclusion=exclude` and a `HOLD` reason: they are not part of the phase-1 manifest, and activating them needs a frozen V10 protocol and a new manifest version.  If activated they form a separate block (original_split = test) that is reported next to the V9-DEV block and never pooled with it, as V9 did.
- `exposure` uses the preflight vocabulary {used_for_design, never_read, unknown}.  Every row is `used_for_design`: read by an earlier project stage with results known before V10 runs (section 3).  For the test cores this means "read once as V9-G1's confirmation"; the V10 package's design snapshot (historical host commit 27117c9, 2026-10-16T01:49:26Z) predates the test results commit 411248e, so the package design is not shown to have used the test results, but the project knew them before any V10 execution and the V10 rule (design §4.3) makes them development / repeat-benchmark data either way.  No row is `never_read`; no row is `unknown`.
- `source_version` records the release, the source archive (member) and the per-file sha256 recorded by R6 REG-P1 / REG-P3 prepare or the V9-G1 frozen list.  T00 did not re-hash any image (metadata-only rule); sizes were checked with `os.stat` where a reference exists.
- `original_split` = official split (BF–SHG train / validation1 / validation2 / test); EPFL has no official split (`none_official`).  `resize_factor` = model px per native px (BF–SHG 0.25: ×4 area downsampling to 512 px; EPFL 1.0: one 512 × 512 native window; empty for excluded EPFL pairs, which have no window).
- `alignment_note` carries the per-pair REG-P3 alignment-check values (EPFL) or the dataset-level alignment statement (BF–SHG).

Relations that metadata cannot resolve (recorded, not fixed):
- BF–SHG patient / tissue-block mapping is not published: the core is the verified unit; patient-level independence of FIT / CAL / DEV / TEST is unverified.  86 TMA grid positions occur on both slides 1B and 2B (role pairs of those positions: CAL / DEV 1, CAL / TEST(V9) 7, DEV / FIT 7, DEV / TEST(V9) 16, FIT / FIT 3, FIT / TEST(V9) 15, TEST(V9) / TEST(V9) 37).  Whether 1B and 2B are sections of one block (same tissue at the same position) is not documented; if they were, those positions would be the same specimen in two roles.  No image was compared to test this (metadata-only rule).
- EPFL near-duplicate detection (REG-P3) compares only scenes of the same category whose half-resolution ÷ 16 thumbnails have identical shape, at correlation > 0.9; near-duplicates across categories, between differently shaped crops, or below 0.9 (for example consecutive captures of one place) are not detected.  3 of the 13 links involve an excluded scene (those scenes carry the linked unit as `group_id`).
- EPFL release alignment is the authors' SIFT / RANSAC similarity registration: REG-P3 keeps pairs whose best integer shift is within ±1 half-resolution px, i.e. a residual of about 2 native px; the strict 2.25-native-px threshold sits at that limit and recovers a known synthetic transform, not the sensors' true correspondence.
- Two on-server copies of EPFL are the same release (identical PROVENANCE.json and archive sha256; same names and sizes): P60 read the home copy, R6 / V9 read the `/projects` copy.  Any path-based role check must treat them as the same records.
