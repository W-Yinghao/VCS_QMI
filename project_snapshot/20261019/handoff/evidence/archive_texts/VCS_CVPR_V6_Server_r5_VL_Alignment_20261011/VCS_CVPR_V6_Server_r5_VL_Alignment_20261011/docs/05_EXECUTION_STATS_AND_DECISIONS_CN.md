# r5 执行、统计与分支决定

## 1. 权限与版本

本包是实施建议和代码参考，不是已执行作业。服务器接入后按真实最新授权处理：只读盘点／测试／既有模型重读可按当前权限开展；新增6次完整训练需有覆盖本批的预算与执行批准。若已有明确批准，登记来源后执行，不机械反复申请；若没有，先报告资源与协议。

不自动取消已获批任务，不改冻结协议，不删除旧结果，不开官方评价，不重启关闭的SSL/R线。原仓库函数的修复、新分析与新训练分开提交，注明参考HEAD。

## 2. R5-30：六次完整微调的最小配置

- `datasets = refcocog, refcocoplus`。
- `backbone = siglip2_b16`，权重ID沿R4-VL1原始预训练模型；hash必须核对。
- `objective = distribution_softmax`。
- `seeds = 0,1,2`，不按seed0结果筛选。
- FIT候选与正矩阵、查询过滤、图像角色、tokenizer、crop transform全部沿R4-VL1。
- 双塔完整更新；不是训练冻结特征头，不从R4-VL1最佳VCS/JS权重起步。
- 10 epochs、AdamW encoder lr=1e-5、weight decay=0.05、warm-up=200、余弦日程、有效batch=32图。
- critic优化组、a/b参数化及lr从实际代码复用；确认softmax使用2f，而不是只读注释。
- 新分支a/b初始化同R4-VL1 `(10,-2.5)`；b在softmax排名中抵消属于数学性质，不额外改其优化组。
- 精确chunk accumulation按同一32图batch总和归一。硬件内存相关chunk规则照实际现有实现，记录GPU/精度/有效chunk；不宣称数值逐bit一致。
- 每epoch在CAL全候选Acc@0.5选择，平局最早epoch。DEV保留原先允许的step0复现检查与选定模型一次读数；不逐epochDEV筛选。
- 全程记录训练损失、CAL任务、所选epoch、所有门槛、失败/恢复、参数漂移、时长/显存。新目标分目录，不覆盖旧softmax。

### 复现与代码门槛

1. 有效real candidates完整进入分母。
2. 同一输入的单合法框：distribution与set损失/梯度一致。
3. 多合法框：D2恒等式及自动微分检查通过。
4. padding值改变、增加padding、空查询不会改变有效损失；padding梯度为0。
5. 没有合法候选的DEV查询仍在主指标中。
6. 精确chunk与joint计算的loss/grad在指定dtype误差内一致。
7. 保存fp32所选权重并回读复现实际选定输出；沿用R4精度经验，不只存fp16临时副本。
8. 小图数smoke只验证代码，不以它的DEV高低选择学习参数。

### 新对照要导出的字段

每图/查询/候选stable IDs、cosine、selected a/b、合法掩码或IoU、检测分数、任务命中、common J、集合概率、合法集合KL。早/中/晚已约定锚点若能在CAL/FIT导出则保存；DEV不额外用来选择。

运行时间须来自新分支端到端smoke；给出每run/总量的估计区间、GPU型号和排队限额。旧报告的1–4小时只能作为历史运行，不当作保证。checkpoint与评分缓存优先放已有授权目录，空间不足先报告，不删除旧文件。

## 3. 统计输出

### 主表

每个数据集分别报告三个训练seed的Acc@0.5均值、样本标准差、每seed数值、配对差及t区间(df=2)。主差值：D−E，次差值：VCS−D、JS−D。若支持总体表述，列出两个主差值的多重性处理；不能只选择区间不含0的数据集。

R4-VL2相关差值保持C1–C4原结果，同时补F1、可做时F2。两数据集共享家族，合并均值仅描述，不将两个数据集×三个seed当作六个独立领域样本。

### 分层和诊断

Bootstrap按图片，沿所有方法/seed共享抽样索引。先每query平均重复候选抽样，再图内平均，最后跨图片平均。图片bootstrap区间条件于已训练模型；训练seed区间表示训练随机性；二者不替换。DEV被反复使用，因此全部研发分析标探索性。

固定checkpoint的J_G区间使用图片级统计，不按候选数或pair数构造虚假的大样本。R4-T2只验证标准实例，不在新报告中升级为“新置信估计器”。

### 对“接近”的表述

区间跨0：报告“当前区间包含0”。等效/非劣要求事先独立定义实用margin；本包没有根据已见结果指定一个保证过关的margin。新margin需在最终独立评价前确定，依据用途与可接受代价，不依据当前DEV能否通过。

### 缺失

缺seed不填均值为三seed、不藏OOM、不用smoke替代正式结果。任一共同比较缺输入hash或正确选择记录，列为不完整；只重做缺口，不重跑整个项目。

## 4. 条件方案：语义参考，默认不启动

仅在以下证据共同出现时考虑起草：检测分数参考没有将足够质量分给真正危险的语言相关干扰；在共享候选诊断中可复现；分布式softmax控制不足以解释剩余差距。这里没有根据DEV挑选必胜数据集的许可。

候选定义为：

$$\nu_\lambda(r\mid w,G)=(1-\lambda)/m+\lambda\,\operatorname{softmax}_r(s_{teacher}/\tau).$$

teacher冻结且同一套权重服务所有方法；λ<1确保支持。τ/λ的规则仅用FIT/CAL事先设定，范围受预算控制。不得用DEV错误名单设权重，不得用真值剔除“教师觉得难但标签为正”的项。Q包含合法框不构成bug。

这是新的query-dependent参考Q，原来的J仍可用，但不是原条件乘积QMI。以logν+2f修正排名；若为了强调某些样本而importance-reweight恢复原Q，那么它只是采样改变，不应宣称换了目标。

如做：VCS和JS均获得同样ν和完整训练机会；集合softmax保留、共享教师信息的评分控制保留。先明确与NCE/困难负例/参考分布设计已有工作的关系，再决定论文如何归属。不能仅更换ν就宣布跳出RPC。

默认本轮新训练数仍为6；任何语义ν训练另立协议与预算，不算作隐含额外任务。

## 5. 不采用的自动补救

不自动引入背景/图像上下文新分支、Large主干、文本生成、CLIP+λJ、闭集分数零阈值拒绝、跨图候选池、污染全网格、冻结特征MLP搜索。若后续诊断真的指向输入缺少空间关系，可单独提出，但本轮不与目标对照混合。

检测器FIT见过FIT图片的限制继续披露；没有必要为了这一对称任务对照立刻再训检测器。若最终泛化结论依赖这点，再提出独立held-out proposer实验。所有方法仍用同一检测器和相同候选。

## 6. R5-40：从研发结果走向最终评价

第一份产出是协议，不是读取成绩：

- 明确将哪些算法固定为最终方法，基于什么CAL规则选择。
- 保留uniform VCS、matched JS、集合softmax及有解释价值的分布式softmax控制。不要只挑DEV有利的一格作所谓确认。
- 说明官方全任务和当前≥2 referred objects开发子集的区别；保持两张表。完整任务中的无候选/未覆盖必须按统一规则算错。
- 核查图片ID/模型/检测器预训练与任务训练暴露。RefCOCO家族重叠不是独立外域。
- 明确标准query-level与研发image-macro指标及其分母，不把二者混列。
- 外部系统按输入与训练监督分层：给定框、检测提议两阶段、端到端grounder不能混成纯损失对比。
- 官方val曾用于外部模型复现等，不能写成全项目从未见过；官方test是否未读以实际暴露台账核实。
- 官方集单独授权；一次固定脚本生成所有预定行。首次正式读取后的修复只限实现错误并完整记录，不以调参读取替代确认。
- 论文仍为V6，先改证据表及主张草案；本包不自动重写主稿或更改投稿场馆。
