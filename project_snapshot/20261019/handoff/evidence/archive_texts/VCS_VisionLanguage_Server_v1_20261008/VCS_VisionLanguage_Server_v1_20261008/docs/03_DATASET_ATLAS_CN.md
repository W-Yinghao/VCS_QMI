# 可用数据集与选择路线｜VCS-VL v1

**核查日期：2026-10-08。** 下面列的是18个数据／任务条目，不是18个互相独立的图片来源。每个条目都区分原生用途与本方案建议用途。入口和论文来自原作者、官方数据站或官方实现；本轮未下载图像，服务器仍需确认许可、文件可达性、版本和校验。

## A. 总览与优先级

| ID | 数据条目 | 原生标注／评价 | 本方案用途 | 顺序 |
|---|---|---|---|---|
| D1 | Flickr30k Entities | 实体短语、共指、框 | 第一主任务：同图区域—短语匹配 | 首轮 |
| D2 | RefCOCOg（UMD） | 较长指代表达、目标对象 | 上下文依赖、第二数据集 | 主扩展／替代 |
| D3 | RefCOCO+（UNC） | 指代表达、目标对象 | 属性／外观歧义 | 任务偏简单时 |
| D4 | RefCOCO（UNC） | 指代表达、目标对象 | 指代任务的另一标准设置 | 扩展 |
| D5 | Visual Genome | 区域描述、对象、属性、关系 | 多对象关系与更多局部标注 | 清理能力具备后 |
| D6 | GQA | 场景图、问题、答案、功能结构 | 从训练场景图派生关系核对，不强开VQA | 诊断 |
| D7 | DCI | 密集描述与子区域mask | 长／细描述的区域检索 | 主要备用 |
| D8 | DOCCI | 长人类描述与图片 | 细节丰富的整图检索 | 全局备用 |
| D9 | PhraseCut | 短语、区域mask、属性/关系词 | 固定mask候选匹配或区域验证 | 局部备用 |
| D10 | CLEVR-Ref+ | 合成场景、指代表达、程序、框/mask | 有明确关系结构的诊断 | 数学/关系诊断 |
| D11 | COCO Captions | 整图多caption | 保留旧缓存的精确图文检索 | 全局备用 |
| D12 | Flickr30k Captions | 整图多caption | 与D1同源的双向检索检查 | 低增量成本 |
| D13 | CUB-200-2011＋Reed descriptions | 鸟类图片、细粒度文字；原图另有框/属性 | 细粒度自然图文匹配 | 非场景类备用 |
| D14 | SugarCrepe | 正caption与困难负caption | 整图语义正确性 | 只做冻结评价 |
| D15 | SugarCrepe++ | 两个同义正caption＋一个负caption | 同义性与细微语义变化 | 只做冻结评价 |
| D16 | ARO | 属性、关系、词序 | 错误类型分析 | 只做冻结评价 |
| D17 | BiVLC | 双图双文、双向困难匹配 | 避免只擅长图→文 | 只做冻结评价 |
| D18 | RefCLEF / ReferItGame | 自然图片上的指代表达/区域 | 数据获取或COCO重叠限制时 | 后备 |

### 推荐的三条紧凑组合

**默认：D1训练／验证 → D2独立扩展。** 主要结果是区域匹配，不强制跑所有组合性基准。

**细描述路线：D7 → D8。** D7做局部区域检索，D8做整图细节检索；不能把缺少框标注的D8当局部grounding数据。

**低成本全局路线：D11或D12 → D15＋D17。** 必须先排除COCO/Flickr测试图片与训练重叠；这是一套明确的精确对应／多描述协议，不能恢复旧主题配对R2设计。

## B. 主任务数据的接入卡

### D1｜Flickr30k Entities

**来源事实。** 官方版本包含31,783张图片、每图5条caption的实体／共指／框标注，并提供其使用的train/val/test文件。图片获取与注释仓库分开；图片使用受原条款限制。[D1]

**入口：** https://github.com/BryanPlummer/flickr30k_entities

**服务器动作：** 优先复用已有Flickr图片目录；下载/读取注释，核对image ID是否完整；直接采用对应版本官方split。恢复sentence中的phrase/entity链接与XML中的box；记录多box、无box、scene类对象。

**本方案建议：** 单框实体作机制开发，完整实体集合单独评价；不能把单框子集成绩写成官方全量成绩。同一实体在不同caption里的指代必须合并为正例集合；复制的alias不多算独立监督。至少两块合格候选的图片才进入主要条件关系实验。

**最适合：** 冻结双塔下的低数据配对学习。**风险：** 短语短、歧义多；无框或多框处理会改变样本；官方图像可能需要登记获取。

### D2–D4｜RefCOCOg / RefCOCO+ / RefCOCO

**官方API：** https://github.com/lichengunc/refer

**论文：** https://arxiv.org/abs/1608.00272

官方API支持三者及多个划分。RefCOCOg建议UMD图像级划分；Google版本存在不同的划分约定。RefCOCO+的采集限制位置表达，更侧重外观辨别；RefCOCOg的表达更丰富。具体语料以下载版本的注释为准。[D2,L7]

**服务器动作：** 分别记录`dataset`和`splitBy`，连同COCO image ID作为跨数据去重键。旧UNC下载服务器失效时按作者仓库提供的issue路线查受支持镜像，不自行将未知重打包标注当官方版本。API代码license不等于图像license。

**建议用途：** D2优先补上下文；D3用于同类对象外观歧义；D4保留位置词场景。标准testA/testB与val各自报告，不混成未经说明的总分。

**特别限制：** 这三套数据共享许多COCO图片，不能称为三套完全独立的视觉域。训练一个数据集后测试另一个要先按基础图片去重；保留全部原协议结果时应标“跨标注任务”，不是“未见图片泛化”。

### D7｜Densely Captioned Images（DCI）

**入口：** https://github.com/facebookresearch/DCI

**来源事实。** 作者提供7,805张图片的密集描述，许多文本对应子mask；图像来自SA-1B，获取需接受对应许可。仓库已归档；官方还提供生成摘要/负例的CLIP-ready版本。[D7]

**服务器动作：** 不下载整个SA-1B；按官方说明只取得必要图片包。原始长描述、短标题、生成摘要分别打字段，不混称全部人工短caption。记录token截断；一个基础图像的所有mask/描述留同一split。

**建议用途：** 区域—详细描述匹配，或部分图像内容检索。适合短实体词不足以区分候选时。若使用mask bounding crop，应注明没有进行像素分割；全图与局部query分表。

**主要风险：** 多区域来自同一图片导致伪样本量；长文本超过模型上下文；部分公开测试变体的基础图片数较小，须按基础图做区间，不能按成百上千mask计算独立N。

### D9｜PhraseCut

**入口：** https://github.com/ChenyunWu/PhraseCutDataset

**来源事实。** 作者基于Visual Genome构建77,262张图、345,486个短语—区域样本，标注包括mask及类别/属性/关系词。提供train/val/test和100图miniv；miniv与val文件的组合规则要按官方说明。[D9]

**建议用途：** 先用已给mask或其框作为候选，比较配对打分；预测mask才使用官方mask-IoU指标。含多个实例的短语不能强行缩成一个物体。

**主要风险：** 若没有新分割头却宣称分割方法，会夸大任务范围。它和VG/GQA有来源重叠；训练前排查下游ARO等测试的共享图片。

## C. 备用数据与各自改变的问题

### D5｜Visual Genome

官方入口 https://visualgenome.org/ 。区域描述、对象和关系图可用于局部关系学习。本文不引用未经统一版本核对的精确样本数；官方页面本次自动解析未成功，下载可达性需服务器确认。可通过GQA官方说明追溯其图像与场景图来源。[D5,D6]

**用途：** 在主任务已有效后增加训练对应。**要做的清理：** 对象/区域重复、关系遗漏、同义词、外部benchmark图片重叠。未标注关系不自动是错误对应，因此更适合构造明确的采样分布，而非声称完整语义真值。

### D6｜GQA

官方入口 https://cs.stanford.edu/people/dorarad/gqa/download.html 。下载提供问题、场景图及相关数据；本方案只使用训练侧场景图构造关系诊断或候选描述，不自动转向开放式VQA。[D6]

**用途：** 判定关系信息是否需要上下文，或检查词序/主体客体交换。派生短语集要有自己的版本名、生成规则和人工核对；不能把派生匹配准确率命名为官方GQA问答准确率。

### D8｜DOCCI

入口 https://google.github.io/docci/ 。作者提供15k图片和长人工描述，目标覆盖细节、空间关系与计数等；官网说明图文为CC BY 4.0。[D8]

**用途：** 全局细描述检索。**不适合：** 原生区域定位，因为没有与本方案等价的完整区域对应图。需要长文本处理，先用原模型规定的token上限做审计；分句汇聚属于新增共同模块，不只给VCS。

### D10｜CLEVR-Ref+

入口 https://github.com/ccvl/clevr-refplus-dataset-gen 。提供场景、指代表达程序与框/mask生成工具，依赖CLEVR场景与较旧的Blender流程。[D10]

**用途：** 定位局部颜色/形状、关系词、多个相似对象的失败原因。首轮用可取得的数据或少量固定场景，不自动申请大规模渲染。场景结构真值可以验证任务；只有另外完全指定的概率采样模型才有S的oracle。

### D11–D12｜COCO Captions / Flickr30k Captions

入口分别为 https://cocodataset.org/#download 和Flickr官方图片站（可从D1作者仓库进入）。

**用途：** 在服务器已有整图特征时，实施最省资源的精确对应／多caption学习。所有同图caption作为合法正例；不把同主题的另一图caption默认标成正例。用官方或明确版本的检索划分，1k/5k候选池分别报告。[D11,D1]

**主风险：** COCO 2014/2017与常见检索划分不是简单互斥；SugarCrepe/BiVLC引用COCO val2017，ARO也使用COCO/Flickr来源。用image ID和图像hash做排除，不仅按目录名判断。

### D13｜CUB-200-2011＋细粒度文字描述

图片/属性入口 https://data.caltech.edu/records/65de6-vp158 ，文本入口 https://github.com/reedscot/cvpr2016 。原CUB含200种鸟及框、部位、属性标注；Reed工作另提供birds/flowers文本资源。[D13a,D13b]

**用途：** 鸟类外观描述检索、少配对适配。它提供与COCO场景不同的细粒度问题，不需要新的大模型。

**注意：** 原CUB划分和Reed零样本类划分是不同实验。按图像分割任务不能宣传未见类别零样本；基础大模型可能预训练见过测试类别/图片也需披露。文本包实际可达性与原图授权分别确认。另有Flowers文本可用，但本轮不自动增加第四个任务。

### D18｜RefCLEF / ReferItGame

入口为D2的官方API，需要相应自然图片集合，不是COCO图片。适合已有该库存或需要避开COCO重叠时使用；具体采用UNC还是Berkeley划分在运行前锁定。[D2]

## D. 只做冻结评价的数据

| 数据 | 正式入口 | 主要评价 | 必须处理的限制 |
|---|---|---|---|
| D14 SugarCrepe | https://github.com/RAIVNLab/sugar-crepe | 正caption vs语义困难负caption | 基于COCO val2017；不得又用于适配训练 |
| D15 SugarCrepe++ | https://github.com/Sri-Harsha/scpp | 两个同义正描述是否都优于负描述 | 同义正例不是重复监督，沿官方评价规则 |
| D16 ARO | https://github.com/mertyg/vision-language-models-are-bows | 属性、关系、词序子任务 | 来源含VG/GQA、COCO、Flickr；各子集分开排重 |
| D17 BiVLC | https://github.com/IMirandaM/BiVLC | 两图两文的双向匹配 | 含生成困难图像；不作为原生自然图像真值，也不拿其test调参 |

这些任务不是Flickr区域模型的必过门槛，也不自动提供fine-tuning训练划分。只有适配目标确实覆盖整句/全图时才成为主评测。若文本单独就能区分正负，应把其作为benchmark偏差控制，而不是说图文依赖已学好。[D14–D17]

## E. 服务器必须返回的数据可用性表

逐条填：官方入口、下载时间、注释版本/commit、图片实际数量、split计数、文件checksum、许可证确认人、存储大小、缓存来源、重复图片数、缺失率、token截断率、标注不完整处理、初始资源预算。

**可用性优先级不等于效果选择。** 若D1不可取得，可以在跑任何主EVAL之前换D2；若看了D1结果后才换D7，要保留D1为探索记录，并对D7做新的预注册。不同来源的同图区域、caption或mask不能充作独立图像重复。
