# 0. 本轮要完成什么

**主问题：在有限对应标注下，VCS 能否从预训练视觉与语言特征中学习更有效的配对证据，完成区域—短语匹配？**

首选 Flickr30k Entities：先冻结双塔，比较配对评分器；再用一个小规模、完整的 adapter 实验检验是否改善任务。RefCOCOg（UMD）作为主要扩展／数据不可用时的替代；DCI 作为描述更细、自然歧义更强的备用路线。

这是一项 **estimator 的视觉—语言应用**。使用区域／短语标注的实验必须称为有监督对应学习，不称为无标签 SSL；原图像 SSL 与 ImageNet 工作继续，本文档不取代它们。论文仍是 V6，本包的 v1 只表示新增 VL 执行方案版本。

| 层次 | 固定什么 | 学习什么 | 最终要交付什么 |
|---|---|---|---|
| A：估计器 | 图像、文本编码器及配对分布 | 有界 critic | 同目标 J／平方风险、有限模型真值误差、成本 |
| B：匹配任务 | 数据、候选、预训练双塔 | 评分头；随后可加 adapter | 区域选择准确率、样本效率、困难子集表现 |
| C：外部验证 | 冻结选定方案 | 不在测试集调参 | 第二数据集、固定提议 grounding 或多描述检索 |

**最小首轮不是全数据集大网格。** 完成一个数据集、一个小型评分器族、同一批对照及对应误差分析。替代路线由失败诊断触发，不同时铺开。

本方案采用三种来源标记：[O] 是合作者原计划／补充；[R] 是已提交项目结果；[D]/[L] 是本轮核查的公开数据／文献；未注明已完成的实现参数、阈值和实验安排均为 **本次建议**。来源表见 `docs/05_SOURCES_AND_RELATED_WORK_CN.md`。

**主要替代：DCI 的区域描述。** 当 Flickr 的短语太短、基础模型接近天花板，或重点转向更细描述时采用。原描述与官方 CLIP-ready 生成摘要分开；所有子区域随基础图片划分。[D7]

完整清单见 `docs/03_DATASET_ATLAS_CN.md`，覆盖 18 个数据条目。首轮只下载选定数据的必要部分；官方索引可访问不代表所有图像可直接下载或许可已获接受。

## 2.2 数据角色

保留官方 train/val/test。仅在 train 中按**原始图片身份**划出 FIT、CAL、DEV：建议 CAL、DEV 各 10%，其余 FIT；在数据清理后冻结确切计数。

- FIT：评分器／adapter 更新；训练规模取 1k、4k、16k 张**不同图片**，使用同一固定随机排列的嵌套前缀。
- CAL：估计器超参数与停止选择，比较同目标 J。
- DEV：任务参数与备用路线选择，比较区域选择准确率。
- 官方 val：选定配置的外部验证，不再同时无限调参；官方 test 只在方案冻结后评价。
- 首轮同一 FIT 子集下运行 3 个初始化 seed。它们不是 3 次独立的数据抽样；最终确认可补一个事先固定的 FIT 子集 seed。

如果可用 FIT 图片不足 16k，使用所有实际 FIT 图片，并保留 1k/4k；不得复制图片凑足 N。外部测试只有单一测试划分时，用训练侧 DEV 做开发，不能将测试集再当 DEV。

# 3. 从对应关系到原始 J：必须写对的概率对象

## 3.1 一张图片内的对应矩阵

一张基础图片记为 G；合格候选区域为 r=1,...,m，短语为 w=1,...,k。构造兼容矩阵 A，A[r,w]>0 表示已标注对应。对共指别名、同一文本的重复出现、多个合法区域做显式归并；不能只认 caption 的一条对角线。

主协议先均匀采样区域，再按该区域关联的有效短语采样：

$$p_G(r,w)=\frac1m\frac{A_{rw}}{\sum_j A_{rj}},\qquad
q_G(r,w)=p_G(r)p_G(w).$$

所有区域必须有至少一个有效短语，所有保留短语至少有一条有效边；否则移到 exclusion 表，不能隐式补一个假对应。于是区域边缘 p_G(r)=1/m。基础图片等权；不会因为一张图片标注更多而在损失中占更大权重。

总体对象为

$$P=P_G P_{R,W\mid G},\qquad Q=P_G P_{R\mid G}P_{W\mid G}.$$

评分器输入来自图片／区域／短语的内容，**不输入图片 ID、entity ID、ground-truth 关系矩阵或原始标注类别**。这些 ID 只用于采样、划分和评价。若评分器只看区域与短语而不看 G，它属于同一条件实验中更受限的函数类；不能把有限类最优值写成任意条件密度比的精确解。

## 3.2 Q 不等于“所有语义错误组合”

Q 的独立抽样可能抽到合法对应，这是产品分布本身的性质。二元机制标签 C=+1/-1 表示来自 P 还是 Q，不是自然语言真／假标签。

**不能从 Q 中删除所有正边，然后仍称其为原来的条件 QMI。** 专门构造语义相近且错误的负例会得到 Q_hard；原 J 仍可比较 P 与 Q_hard，但应标为另一种参照散度的任务实验。

因此主阶段先精确枚举 q_G；困难条件优先采用**评价子集**而不改变训练目标。需要 hard-negative 训练时另登记协议，对所有损失共同使用；必要时用有完整支持的提议分布及重要性权重估计原 Q，报告权重方差，不暗中排除正质量。

## 3.3 损失与数据加权

令 T=tanh(f)。每张图的变分值为

$$J_G=\sum_{rw}p_G(r,w)(T_{rw}-T_{rw}^2/2)
 +\sum_{rw}q_G(r,w)(-T_{rw}-T_{rw}^2/2).$$

训练损失为 1-mean_G J_G。等价的平方损失为

$$L_G=\tfrac12\sum p_G(1-T)^2+\tfrac12\sum q_G(1+T)^2.$$

**正负总权重都为 1/2**。不同图片的矩阵大小不同，先图内归一化再图间平均。padding 元素不得参与均值。混合参考 CS 的变换只用于附加显示，不在 S 接近 1 时拿变换后的方差宣称稳定。[O1]

## 3.4 为什么这个对象能服务区域选择？

理想 critic 满足

$$\frac{1+T^*}{1-T^*}=\frac{p_G(r,w)}{p_G(r)p_G(w)}
=\frac{p_G(r\mid w)}{p_G(r)}.$$

当 p_G(r)=1/m 时，固定 G,w，按 T* 排序与按 p_G(r|w) 排序相同。如果区域先验不均匀，排序应基于

$$\log p_G(r)+2f(r,w,G),$$

而不是只按密度比。实现用 logit 排序，避免 tanh 在浮点数中饱和后产生人造 ties。该联系是原 gap 的本轮应用推导，不是声称区域匹配算法从未出现过。[O1]

## 3.5 三个重要限制

**固定特征上的正增益仿射余弦不会改变排序。** 当 f=a(cos-kappa)、a>0 时，只调 a/kappa 可以改善概率刻度和 J，不能提高 Top-1；出现大量 Top-1 变化先查候选、tie 和数值问题。要改善排序，需要联合评分网络或适配表示。

**原始标注图不能无条件充当自然分布的 oracle。** 在精确的有限、可识别输入模型中可以计算真值；真实特征可能把不同状态映射到同一个输入，必须对碰撞状态合并后计算推前分布。未标注关系不自动代表语义错误。本轮主要图像指标是 held-out J/风险与任务结果，不填写自然总体 posterior MSE。

**候选数量会改变目标难度。** 若有 m 个均匀、确定的一一对应状态，原定义给出 S=(m-1)/(m+1)，并非模型越好才使 S 更大。一般可控通道 P=rho*P_match+(1-rho)*Q 有

$$S=\frac{\rho^2(m-1)}{[2+\rho(m-1)](2-\rho)}.$$

所以不同数据集／候选数的原始 J 不直接排名“信息量”。同时报告 m、正边密度、采样律；在固定候选数分层内比较方法。附带代码验证这些恒等式。

# 4. Flickr30k Entities 的实际解析

## 4.1 标准样本记录

每张图片保存唯一记录：数据集及版本、官方 split、原始 image ID、图像路径与校验、宽高、区域框、实体 ID、短语文本、caption ID、alias group、合法目标集合、排除原因。

主开发协议先选择 **single-box entity**，其短语唯一指向一块有效框，且每图至少两块合格区域。多框、无框、scene、缺失图片和歧义项单独计数。开发子集结果标明 filtered single-box；不能将其冠名为完整官方 benchmark 结果。

第二阶段必须做完整的标注处理：依据官方 API 的实体与多框约定，保存 target-set；可以用预先确定的 union-box 或集合命中规则，但两者分表，不能评价时任选。官方 phrase-grounding 数字只使用其规定的框与 IoU 处理。[D1]

## 4.2 框和图像预处理

读取实际 XML/JSON 确认坐标是 0/1-based、xyxy/xywh、端点是否包含。转成统一连续坐标后 clipping；非法框不静默修成整图。抽 100 张 TRAIN 图可视化验证，不用 OCR。

主输入为 tight crop，使用所选预训练模型的官方变换；不对局部短语任务默认加入会截掉目标的 random resized crop。位置短语不能在翻转图片后保留原文不变。提取前保持 RGB／归一化／输入分辨率一致。

若主任务存在明显关系／位置短语，单设 context 输入条件：10% 外扩 crop＋完整图像特征＋归一化 box 坐标。该修改所有方法同时采用；context ablation 不与原 crop-only 数字混排。

## 4.3 候选集合

首轮使用图片中全部合格标注实体框，顺序按与文本无关的 hash 固定后再一致打乱。真实答案框不能因为排在第一位被读出。

这属于 **给定标注候选的区域匹配**，不是端到端 grounding。后续统一使用固定、query-independent 的区域提议器或现成 proposals，报告 proposal recall、Top-1 IoU 成功率和查询耗时；proposal 未覆盖真值也应计入总体分母。

标注候选训练后直接移到 proposals 是分布变化，需单独报告。要对 proposals 再训练，则重新定义其 P/Q 和覆盖规则；不能用当前 query 的真实框筛选测试 proposals。

# 5. 编码器和评分器

## 5.1 固定双塔

建议首轮统一 CLIP ViT-B/16、224 输入。服务器可优先使用已缓存且 provenance 完整的兼容权重；若只有旧 ViT-B/32，先用其完成实现检查，但比较主表不混用双塔。

记录权重来源、revision/checksum、特征输出位置、特征维数、tokenizer 与 context length。缓存 fp16 可节省磁盘，训练前转 fp32；先和 fp32 提取做误差及排名核对。不能以不同库加载同名模型却不核对预处理。

长文本单独记录超长比例。Flickr 短语优先原文；DCI/DOCCI 使用原描述或官方短摘要各自标明。不得只给 VCS 长上下文模型、其他方法则截断到短上下文。[D7,D8]

## 5.2 评分函数类

| ID | 实现 | 作用 |
|---|---|---|
| F0 | 原始 CLIP cosine，不训练 | 基础能力和适配漂移参照 |
| F1 | a*cos+b，a>0；tanh 输出 | 低容量标定参照，不期待排序改善 |
| F2（主） | concat(u,v)→256→256→1，GELU，T=tanh f | 学习配对关系；比较 VCS 与 JS 必须完全同类 |
| F2-context（后续） | 同一 F2 加公共上下文和 box 特征 | 只在关系诊断支持时追加，所有损失共享 |
| K0 | concat(u,v) 的 RFF＋ridge／bounded score | 同目标核路线；输入与目标和 F2 一致 |

F2 不含 image-ID embedding；末层小权重、零 bias 初始化，避免沿用旧 a=10,b=-10 的高度饱和起点。先以 float32 做损失；相同学习率不自动意味着优化步长可比，应记录初始和早期的 logit/参数梯度尺度。

输入到核与神经 critic 的归一化、是否含 context 保持一致。RFF 的带宽和特征数要在当前数据集上选，不能只转移旧 CIFAR 超参数后宣布核方法上限。

# 6. 外部对照与拟合规则

## 6.1 对照分工

1. **直接 VCS：**最大化原 J，测量用原 J。
2. **平衡 Logistic：**同 f、同 p/q；损失 mean_P softplus(-2f)+mean_Q softplus(2f)。T=tanh f 后读同一 J。
3. **RFF 同目标估计：**用当前数据的带宽选择；ridge 后 tanh 只叫两阶段拟合，不叫完整 bounded J 的精确闭式解。
4. **条件 InfoNCE／多正例候选交叉熵：**在同一图片候选中预测区域或短语；主评价是任务准确率和自身风险。固定数量提议必须记录。softmax logit 的平移自由度没有被解决时，不把它的 tanh 值当成已标定共同 J。
5. **SigLIP／sigmoid 参照：**区域候选中若采用按实际正负计数加权的逐对 sigmoid，名称为“SigLIP-style task control”，记录有效类先验；不冒充原始全局 SigLIP 的完全复现。全局图文备用路线应加入官方形式的 SigLIP。[L2]
6. **外部强预训练模型：**FLAIR、FG-CLIP 或 SigLIP 检查原生任务表现，放单独参考表；额外训练数据／模型尺度不同，不把其与共享 CLIP 特征表混成单因素损失比较。[L3,L4]

不平衡 sigmoid 使用的 logit u 若对应正例先验 pi，转为共同后验时应先减 logit(pi)，再 T=tanh((u-logit(pi))/2)。未知先验不直接算共同标定误差。随机产品负例不是语义假负例标签，原生任务负例与混合机制负例的身份应分开。

## 6.2 超参数与停止

主神经拟合建议 AdamW；lr={1e-4,5e-4,2e-3}、weight decay=1e-4、batch=32 张图片；最多 50 epochs 或 3000 updates（二者先到者），每 50 updates 在 CAL/DEV 检查，连续 10 次未改善可停止。所有方法相同上限，记录最终实际曝光和步数；这是一套新 VL 建议，不覆盖旧 SSL 日程。

RFF 首轮 D=1024，带宽倍数={0.5,1,2}，ridge={1e-4,1e-2,1}，尺度选择复用经过检查的 solver。完整模型选择成本入账。随后可以固定较优带宽做 D={512,2048} 的有限成本曲线，不先给神经无限容量、给核一个极小配置。

每个训练轨迹保存两种预先规定的 checkpoint：

- `estimator_selected`：CAL 上共同 J 最大（VCS/JS/kernel），用于估计面板。
- `task_selected`：DEV 上区域 Top-1 最大，tie 取更早 checkpoint，用于任务面板。

两种 checkpoint 分别报告，不能在 test 上选择更漂亮的一种。InfoNCE 只参与 task/native 面板；如另做后验标定，必须使用独立 CAL 并把该步骤计入预算。强外部模型按官方接口，不参与此 lr 网格。

# 7. 分阶段执行：先小型完整实验，再有限扩展

## 7.1 VL1-00：接入与数据检查

核对旧图文代码、数据、特征缓存、已跑配置；只复用确认兼容的部分。`scripts/robust_r2r3.py` 的 topic/exact 训练关系与本方案不同，不能直接改参数后当同一实验。

交付：数据可用性、合法许可确认、图片级划分、候选数／多框／缺失／超长统计，raw CLIP 在 DEV 上的基础匹配。小型图像 smoke 只验证处理，不作性能主张。

## 7.2 VL1-01：数学与抽样实现检查

运行本包参考测试，再将同样检查移植到服务器：p/q 质量为1、region prior、一图等权、Q 含合法对应、正负总权重、target-set、矩阵 chunk loss/gradient 一致、prior correction 排名、重复 ID 分组拆分。

先在受控有限对应问题上核对真值。以 m={4,8,16}、rho={0.2,0.6,1.0} 生成 9 个条件。无关特征／可逆坐标变换作为后续选项；不把 index lookup oracle 的简单结果当自然图片估计准确的证据。

## 7.3 VL1-10：固定特征，估计与匹配一起看

主数据集、F2 的 VCS/JS/InfoNCE 与 K0，共 4 条路线×3 个 N×3 个 seed=**36 个选定结果单元**。这是小型拟合，不是36个视觉预训练。每条神经路线另有3个 lr 候选；计数时保留所有候选开销。F0 不训练；F1 作为廉价标定检查单列。

主 N=4k，另两档检验样本效率。比较同一数据上 J/平方风险与区域选择，避免只挑其中一个终点。3个 seed 均完整交付，失败和负向结果计入。

## 7.4 VL1-20：轻量适配，默认只做一个中等 N

在冻结双塔的输出后，各加一个 residual adapter：d→64→d、GELU，末层零初始化使初始映射恒等，归一化位置固定。先保持 F1 式几何评分，从而把“重排来自表示变化”与 F2 匹配器能力分开。

用 VCS、平衡 JS、InfoNCE，N=4k，3 seeds：**9 个完整 adapter 单元**。建议 lr={1e-5,5e-5,1e-4}，epochs≤20，DEV 任务选择；a/kappa 在 CAL/DEV 的有限范围内每种损失独立选择并记录总预算。原始 CLIP 作为常驻基线。

不得只跑 VCS adapter。若冻结 F2 已有效而 adapter 普遍伤害原模型，首轮可以以评分器方法结束，不必强行适配。SigLIP-style task control 是该阶段的可追加3-seed比较，不与匹配JS混称；纳入时应完成所有预定种子。

## 7.5 VL1-30：第二数据集与真实候选

先在 RefCOCOg UMD 复用算法家族，数据集内重新选择有限超参数；这称为第二数据集实验。若检验直接迁移，则保持参数且不使用目标训练标注，另外出表；二者不混称。

与第一数据集共享原始图片时必须先去重。已有 Flickr 权重到 RefCOCOg 的直接迁移和目标内微调属于不同任务。候选提议实验优先使用冻结的 query-independent proposals，不追加大型检测训练。

## 7.6 VL1-40：可选组合性／检索评价

只有进入整图或较长描述适配时，才使用 SugarCrepe++、ARO、BiVLC 及 COCO/Flickr 检索。区域评分器在未训练整句任务上差，不直接说明 estimator 数学失效。

以数据身份排除适配训练与上述测试的图片重叠；无法恢复来源 ID 时注明 unknown，不能宣称严格未见图像。保留 image-only/text-only 等捷径控制。引用官方 evaluator，准确复现它的正例集合和方向，不自己发明更有利的平均分。

# 8. 评价、统计与应交的结果表

## 8.1 主表一：相同表示上的 estimator

每格给出 J_common、balanced squared risk、原生训练风险、refit spread、已知目标上的 posterior MSE／数值误差、时间与显存。真实图片的 oracle 字段必须空缺；两方法 J 差仅在同一 P/Q、候选定义和输入条件下比较。

自然数据以图片为独立单位：图内先算 J_G，再对图平均。bootstrap 重采样整张图及其全部区域／短语，不能把每个 pair 当独立样本。保存图级向量以重算区间。量化波动时分开初始化、训练子集、EVAL 抽样；小波动与准确性不等价。[O1,O2]

## 8.2 主表二：区域—短语任务

同时报告：query-weighted Top-1/Recall@1、图片宏平均、Recall@5（候选不足5标明）、MRR、候选数分层、标注目标集合处理、GT候选或proposal身份。对完整 grounding 给出 IoU>=0.5/0.75、候选覆盖和总样本分母；该 IoU 阈值是本方案建议，官方基准另按官方规则复现。

困难子集在跑方法前定义：同图至少两个同粗类别实体、含属性、含空间/关系词、长短语。标签仅用于事后分层，不能直接送给评分器。错误类型样例按固定随机种子抽取，不只挑 VCS 赢的图片。

## 8.3 主表三：资源和外部用途

独立图片量 N、可训练参数、实际 pair 数、模型调用、候选检索/重排序延时、特征提取和拟合开销分开。神经小头与闭式核求解计时都包含选择。大预训练 FLAIR/FG-CLIP 放参考列，注训练数据和监督粒度不同。

## 8.4 首轮读法

建议将 N=4k 的图片宏平均 Top-1 为任务主要终点，CAL选出的共同风险为估计主要终点。小样本曲线和同类对象子集为预定次要终点。

推进依据可以是：相对同目标核路线有实际风险/样本效率收益，且任务不比原CLIP差超过1点；或相对匹配神经对照有可重复任务/成本优势。1点是开发实用门槛，不是理论常数，也不代替最终配对区间。没有超过JS不自动停整个项目：先准确定位共享神经能力与二次目标额外贡献。

一旦看到官方val/test后再改变主终点、难例筛选或数据集，必须把原结果保留并声明新的探索阶段。有限预算内找不到新增价值时，允许该应用留在补充或阶段性结束。

# 9. 结果不理想时：先定位原因，再选一条替代路线

详细操作和阈值见 `docs/04_FALLBACKS_AND_DECISIONS_CN.md`。下表是执行摘要。

| 现象 | 先查什么 | 一次优先改动 | 对应替代数据 |
|---|---|---|---|
| 原CLIP接近天花板 | 候选是否只是随机跨图、是否几乎单目标 | 同图同类子集与长表达，主集合保留 | RefCOCO+/RefCOCOg；DCI |
| 所有方法都差 | 图框、短语绑定、token截断；全局特征是否看不到局部 | crop+context或统一region pooling | RefCOCOg；CLEVR-Ref+诊断 |
| F1只提高J不提高Top-1 | 正单调刻度是否只改数值 | 进入F2或adapter，而非继续扫a/kappa | 不必换数据 |
| VCS训练分数高、held-out差 | FIT/DEV gap、重复短语/图像泄漏、饱和 | 小头／正则／更早选择，所有方法同条件 | 不先换数据 |
| VCS低于JS | 优化尺度、先验、饱和、表达能力 | 一轮公平超参数或“JS初始化→J微调”变体 | 保留原集；不靠换基线赢 |
| J改善、区域准确率下降 | 目标/候选先验、任务与标注图是否一致 | prior correction或重新定义明确任务P/Q | RefCOCOg可能更明确 |
| adapter破坏原CLIP | 恒等初始化、漂移、选模型规则 | 保留冻结评分器；或共享锚定正则 | DCI/COCO轻量全局分支 |
| GT候选好、proposals差 | proposal recall和框精度 | 统一更好提议，不改estimator宣称 | RefCOCOg固定候选 |
| 极小数据学不动 | 每图候选质量与训练信号 | 4k→可用更大N，比较风险下降 | DCI／VG（新来源先排重） |
| 多模态关系确实缺视觉信息 | 更强统一视觉输入是否可读 | 统一FLAIR/FG-CLIP或DINO视觉特征参照 | 同任务重新对齐全部损失 |
| 噪声实验不利 | 干净能力与评价关系，错误类型 | 不将抗噪写主张；回到干净低样本任务 | 不默认找更容易的噪声集 |
| 对强神经对照始终无差异 | 成本／风险／置信区间完整性 | 作为CS用途或阶段性结束 | 不无限切数据找正结果 |

所有替代必须回答一个新的、明确的原因。一次最多启动一条主备选和一项诊断，不把“结果不好”翻译为全数据集网格。

# 10. 服务器产物和第一轮汇报

新代码建议置于独立 `src/vcs_vl/`／`scripts/vl1_*.py`，但先盘点仓库实际接口。下列是待实现功能，不是声称现有 runner 已存在：

- dataset adapter：官方标注→统一图片记录／target sets；
- cache extractor：冻结双塔、区域/短语去重、版本校验；
- conditional pairing：图内 P/Q 精确矩阵、图间等权；
- fitter：VCS/JS/kernel与task-softmax独立分支；
- evaluator：J、图级bootstrap、候选匹配和官方接口；
- aggregator：按dataset/input/scorer/selection/run seed分表。

第一轮交付三个文件：`VL1_INTAKE.md`、`VL1_DATA_AUDIT.json`、`VL1_FROZEN_PROTOCOL.yaml`，以及原CLIP的DEV基础能力和测得的资源预算。模板在包内。报告每条路线的可用性、数据缺口和与已有实验的复用关系；不是只交PASS/FAIL。

随后每轮交主表一/二/三，逐图和逐种子原始数据、失败原因、选定参数、版本哈希、原CLIP对照、总候选搜索成本。论文统一一个 VCS 名称；内部变体单列消融，不把多个ours占满主表。

本包附带的是**数学/损失参考实现和测试，不是已接入仓库的完整VL训练器**。本轮没有下载或预处理新数据、没有评价预训练权重、没有运行新VL实验；新增训练预算通过既有项目流程确认，已获批SSL作业不因本包取消或重启。
