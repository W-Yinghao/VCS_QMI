## 1. 7b7402c 之后仓库发生了什么，对这份包意味着什么

### 1.1 P71/P72：R2、R3 已完成，R3 不成立

服务器按 v2 计划开了四个分支。R 线的 P72 报告已经提交。设定是冻结 CLIP 双塔加 adapter，主题配对训练，向训练正对中注入比例 m 的错配，五种方法同预算。

R3 是用原生分数识别被注入的错配对，不用干净校准集。结果 JS 在四个格子里都最高，且领先幅度随 m 增大：

| 偏移 | m | VCS | InfoNCE | logistic | JS |
|---|---|---|---|---|---|
| animal | 0.2 | 0.880 | 0.885 | 0.879 | 0.896 |
| animal | 0.4 | 0.856 | 0.862 | 0.843 | 0.887 |
| indoor→outdoor | 0.2 | 0.822 | 0.816 | 0.812 | 0.842 |
| indoor→outdoor | 0.4 | 0.790 | 0.797 | 0.756 | 0.833 |

这里的 JS 是平衡 logistic，用与 VCS 相同的正对和 K=8 独立池负样本。报告原话："does not hold (refuted at every cell)"。

R2 被判为"不可解释为鲁棒性"：评价用自己的 caption 检索，训练用主题配对，二者不一致；注入噪声反而让所有方法更接近初始 CLIP，干净检索随 m 上升。从 m=0 到 0.4，各方法离开 CLIP 的幅度是 VCS −11.0 到 −17.9，InfoNCE −10.9 到 −12.3，logistic −4.5 到 −5.9，JS −0.4 到 −0.7。

对这份包的三点影响：

- **包的 4.2 节把"门控解释噪声耐受"写成待验假设，它的第一次检验已经失败。** VCS 在错配识别上不如 JS，而且在同样噪声下离开初始点最远。路线一和路线二不能再以"VCS 更耐噪"为前提。
- **绝对标定分数不是 VCS 特有的性质。** 平衡 logistic 的后验是 σ(2f) = (1+T)/2，和 VCS 完全同一个量。上一轮 P50 里 logistic 原生概率 ECE 高达 0.34 到 0.49，是一比 K 的训练比例把先验吸进了截距，不是损失函数的问题。这一点包里 3.2 节的 JS 控制已经隐含了，但论文定位里要明说。
- **一个未解释的现象值得用包里第 8 节的诊断去查。** 同一预算下，VCS 的 adapter 漂移最大、JS 几乎不动。门控理论预言 VCS 对高置信配对的更新更少，与观测方向相反。P72 的 adapter 已经存在，直接对它们跑第 8 节的门控与梯度诊断，按注入对与干净对拆分，比重训 SSL checkpoint 便宜得多，也更贴近问题。

### 1.2 P73：T1 已冻结并提交

条件检验的公平对照已经进入预注册：按类带宽 HSIC、学习核 HSIC、logit 统计量的 C2ST、用同一 critic 类训练的 JS 统计量；每次重复重新抽取 N；水平检查用 R=1000。读法规则是 JS 在 0.05 内追平即归因于学习型 critic 而非 VCS。

对包的影响：路线三的增量估计要等 T1 出结果。若 JS 统计量追平，增量用哪种 critic 拟合就由 T1 决定，但增量恒等式本身仍只对平方损失成立，见 2.5。

### 1.3 P69 与 P75 尚未提交；负责人决定已记录

E 线和 solo-learn 移植还没有提交。负责人决定：本轮批准，门槛放宽，S2 获准使用官方测试集，oracle 表位置已定。包的阶段 1 与 P69 的 E 线探针重叠，应复用 P69 的数据生成器和 oracle，只增加后验误差、门控和梯度误差三类指标，不要再写一套平行的生成器。

### 1.4 P68：官方测试与选择集一致，且有一个未被利用的线索

22 个格子里，官方测试的线性精度与选择集平均只差 −0.03。8× 预算下：VCS 常规增强三种子 86.65 ± 0.26；VCS 强增强单种子 88.26；调优 SimCLR 88.13 ± 0.07。SimCLR 在 P41 里从未拿到强增强，它的裁剪下限一直是 0.2。这就是第 3.6 节 S4 的由来。

## 2. 对包内数学与数值的核对，以及我另外推出的五点

### 2.1 复现记录

| 脚本 | 结果 |
|---|---|
| support/previous_round/independent_checks.py | 五项恒等式最大绝对误差 2.2e−16；高斯 oracle S 五行与包中表格逐位一致 |
| support/validate_spec.py | 状态 passed；最大误差 3.8e−11，来自有限差分 |

### 2.2 残差候选训练等价于 L2 boosting

固定 T₀ 与 λ，对 U 最大化 J((1−λ)T₀ + λU) 等价于

```
min_U  E[( r − U )²],   r = (C − (1−λ)T₀) / λ
```

这是 Friedman 的梯度提升在平方损失下的一步，步长 λ 起收缩作用，也就是 Bühlmann 与 Yu 的 L2Boost。伪残差 r 的取值范围可达 ±3，tanh 有界的 U 会在难配对上饱和，这是设计使然，不是缺陷。写清这一点有两个好处：可以直接引用 boosting 的收敛与过拟合结果；审稿人不会把它当成新算法。

### 2.3 组合收益有一个事前可算的上界

由包的 5.2 节恒等式，

```
J(T_w) − max_j J(T_j) ≤ E_M[ Σ_j w_j T_j² − T_w² ]
```

右边是字典成员在 TUNE 上的分歧项，不需要 EVAL 就能算。建议作为 go/no-go：分歧项小于预定门槛就不做组合，直接报告。预测：SSL 饱和区里成员在绝大多数配对上同为 ±1，分歧项在 0.01 以下，组合收益不会超过这个数；高斯 I=0.5 和 4 的条件下分歧项明显更大。推翻条件：饱和区分歧项超过 0.03。

### 2.4 高斯情形下观测噪声只是 ρ 的重参数化

对单位方差坐标的高斯对，两侧各加方差 σ² 的独立噪声后，相关系数变为 ρ/(1+σ²)，联合仍是高斯，S_σ 就是 S 在 ρ' 处的值。已用 200k 样本蒙特卡洛核对：

| I | ρ | S₀ | 总 RMS τ=0.1 / 0.3 / 0.6 | 每坐标 σ=0.1 / 0.3 / 0.6 / 1.0 |
|---|---|---|---|---|
| 0.5 | 0.221 | 0.203 | 0.205 / 0.205 / 0.200 | 0.202 / 0.176 / 0.119 / 0.059 |
| 4.0 | 0.574 | 0.804 | 0.802 / 0.802 / 0.788 | 0.795 / 0.736 / 0.561 / 0.319 |
| 8.0 | 0.742 | 0.962 | 0.963 / 0.961 / 0.956 | 0.959 / 0.922 / 0.765 / 0.469 |

两个含义。其一，合成数据上的观测尺度实验不提供新信息，它就是依赖阶梯的另一种参数化，只应作为实现的精确性检查保留。其二，包中 9.1 节的"总 RMS"约定在 d=20 时把噪声定得太小：信号范数约 4.5，τ=0.6 只占其 13%，S 几乎不动。

### 2.5 单位范数嵌入上，现有网格只覆盖了饱和区的边缘

对 d=128 的单位向量，两侧各加总 RMS 为 τ 的各向同性噪声，点积的扰动标准差是 τ·√(2/d)。用 GEOMETRY_DIAG_v2 中的余弦分布模拟（正对中位数 0.96，负对中位数 0.55），只用点积作分数时可达到的 S 为：

| τ | 点积扰动 sd | S_score | AUC |
|---|---|---|---|
| 0 | 0 | 0.975 | 0.998 |
| 0.1 | 0.013 | 0.972 | 0.997 |
| 0.3 | 0.038 | 0.947 | 0.996 |
| 0.6 | 0.081 | 0.849 | 0.986 |
| 1.0 | 0.153 | 0.624 | 0.939 |
| 1.5 | 0.273 | 0.351 | 0.843 |

若噪声只加在包含信号的 25 维子空间内，同样的总 RMS 下 τ=0.6 即可把 S 压到 0.54。

建议：不要预设 τ 网格，改为预设目标 S_σ，例如 {0.95, 0.85, 0.7, 0.5}，在 FIT 上用闭式 critic 反解 τ；同时报告各向同性与信号子空间两种噪声。这与规范 9.1 节"不因 EVAL 更好而临时增删尺度"不冲突，因为标定只用 FIT。脚本和输出在 oracle_analysis/noise_scale_check.py。

### 2.6 增量恒等式是平方损失特有的，这是二次结构的一处真实优势

S_B − S_A = E_M[(T_B* − T_A*)²] 来自条件期望在 L² 中的正交性。对一般正规评分规则，同样的分解是 Bregman 形式：对数损失下增量等于两个后验之间 Bernoulli KL 的期望。KL 版本没有三角不等式，所以包中 7.3 节那条 |√D_T − √Δ| ≤ √E_B + √E_A 的界在 JS 下不存在。换句话说，"用有限 critic 估计增量时误差如何传播"只有在平方损失下有干净的答案。建议把它写进论文主张，而不是埋在 7.3 节。

## 3. 按路线的补充

### 3.1 路线一，有界残差校正

- 把 P48 的闭式 ridge critic 加入字典作为 C3，tanh 包裹版本作为 C3'。它不需要训练，P48 显示它在 held-out J 上比训练出的余弦 critic 高 0.003 到 0.025。
- 加入 2.3 节的分歧项 go/no-go。
- 路线一是否值得做，取决于 P69 测出的 learned/oracle 差距。若高斯条件下学习值与 oracle 相差不到 0.01，合成数据上的路线一就没有空间，只保留冻结表示上的重拟合。
- JS 字典控制没有闭式权重，要迭代求解。这是二次目标的计算优势，记录求解成本时把它写出来。
- 引用 stacking 与 L2Boost 文献，把路线一的 VCS 特有内容明确为"精确 QP 与精确线搜索"，其余是通用模型平均。

### 3.2 路线二，观测尺度

- 网格按 2.5 节改为目标 S_σ 标定。
- 合成高斯上的观测尺度实验按 2.4 节改为精确性检查。
- 补一条机制主张，用现有诊断就能查否。主张：观测噪声把阈值式排斥变成余量要求，从而产生 VCS 原本缺少的均匀性压力。预测：τ 增大时，负配对余弦中位数下降，h 的 Wang–Isola 均匀性更负，与 GEOMETRY_DIAG_v2 中"h 均匀性排序线性精度"的关系方向一致。推翻条件：J 随 τ 下降但均匀性不变。
- 强增强是已经有证据的去饱和旋钮：held-out J 从 0.974 降到 0.877，平均门控 1−S 从 0.026 升到 0.123，约 4.7 倍，官方测试单种子 88.26。它与观测噪声作用于同一机制，成本更低，见 3.6。
- 理论归属：S_σ 属于 Goldfeld 等人的平滑经验测度框架，那里证明了高斯平滑后的信息量有参数速率的估计。引用它，路线二就不是孤立的工程技巧。

### 3.3 路线三，依赖增量

- 等 T1。JS 统计量若追平，增量的 critic 用哪种由 T1 决定；恒等式与误差界仍只在平方损失下成立。
- 补一个不需要 oracle 的一致性检验。前馈网络中后一层是前一层的确定函数，逐层增量应当望远镜求和：各层增量之和等于首尾之差。主张：学习到的 critic 足够接近最优时，Ĵ_B − Ĵ_A 与 D̂_T 在各层的差异都落在各自 bootstrap 区间内，且逐层增量之和与首尾差之差也在区间内。推翻条件：出现系统性偏差，这时拟合误差主导，路线一先行。这是真实数据上少有的可查否自检。
- 2.6 节的 Bregman 说明写进论文。

### 3.4 第 4 节的门控，换一个可查否的场景

R3 已经否定了"耐噪"这条。门控还有一个方向没测：对已经高置信的负配对，VCS 的梯度按 (1−T²) 衰减，SimCLR 不衰减。同类负配对正是这种情形。主张：VCS 负配对梯度中来自同类配对的份额低于 SimCLR。预测：在匹配的 checkpoint 上，同类份额之比小于 1。推翻条件：份额相等或更高。这条与 Chuang 等人的去偏对比学习、Huynh 等人的假负例消除直接相关，成立的话是一个可以命名的机制，不成立就关闭门控这条线。诊断只需要在第 8 节现有记录上按真实类别拆分负配对，成本几乎为零。

### 3.5 第 8 节的诊断，先用在 P72 的 adapter 上

第 8 节要求早、中、晚 checkpoint 上记录正负配对的 T、残差、门控和输入梯度。P72 在 m ∈ {0, 0.4} 下训练好的五种方法的 adapter 已经存在，先对它们跑同一套诊断，按注入对与干净对拆分。要回答的问题是 1.1 节末尾那条：为什么 VCS 漂移最大而 JS 几乎不动。两个候选解释都可以被这套诊断区分：一是 CAL 上选出的学习率与轮数不同，二是门控确实抑制了注入对但干净的主题配对推动了漂移。

### 3.6 S 线补一项：增强强度与两种方法的交互

主张：去饱和对 VCS 的收益大于对 SimCLR。设计：8× 预算，VCS 与 SimCLR 各跑强增强三种子，与各自常规增强的三种子比较。预测：VCS 的增益大于 SimCLR 的增益，同时 VCS 的 held-out J 落到 0.88 附近。推翻条件：SimCLR 的增益不小于 VCS。要提醒的是 solo-learn 的 SimCLR 默认裁剪下限就是 0.08，所以 SimCLR 很可能同样受益。这条要么给出唯一一个 VCS 不落后的对照点，要么把门控解释明确排除。两种结果都值得写。

### 3.7 E 线不要撤掉横向对照

包的第 12 节把"六种 estimator 直接全网格比较"改为先做 VCS、JS 和拟合变体。P69 已经按含 MINE、NWJ、InfoNCE、SMILE 的设计获批。合作者原计划的标题是"stable alternative to MINE"，没有 MINE 行就没有这条主张的证据。建议保留 P69 的行，只按包的意见把指标换成与目标无关的量：阶梯可分度、尾部分位数、learned 与 oracle 的差距、后验 MSE。
