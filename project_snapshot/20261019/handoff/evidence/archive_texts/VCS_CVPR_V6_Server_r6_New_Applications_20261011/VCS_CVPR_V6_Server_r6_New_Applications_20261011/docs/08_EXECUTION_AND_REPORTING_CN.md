# 执行、资源与报告约定

## 1. 接入检查

记录HEAD/dirty tree、r5后新增结果、现有作业与拥有者新授权。读最新报告不等于实时squeue。保留所有原始结果；新文件建议位于独立`reports/R6/`和`outputs/R6_*`，但这里是**建议路径，不是声称目录已存在**。现有脚本接口先核对再包装。

R5-QN只收齐已批准的实验和相应诊断，不自动开启下一条RefCOCO优化。若它出现积极结果仍按原协议报告，并与新应用探索分开。用户授权空闲GPU跑有用任务并不意味着一次性五路线扫全网格。

## 3. 资源

不写未经测量的GPU小时。记录每步时延、数据解码、配对/像素数、独立场景数、峰值显存、收敛选择和完整模型调用数。REG的推理优化次数与训练成本分列；GAIN计算包括策略自身开销。

两条优先线的controlled检查均可进行；自然pipeline首轮只选择一条。建议pilot有三个固定种子/拆分重复，不按DEV挑最优。一旦需要额外大数据、付费下载、账户许可、特定医学数据，先解决访问与授权，不绕过。

当前Python参考代码只需要numpy；不安装/升级服务器全局PyTorch环境。新训练环境使用独立环境，记录git SHA、版本、缓存与checkpoint hash。

## 4. 数据

同一基础图片的patch、同一组织芯片、同一演员的视频、复用音频、邻接影像不得跨角色泄漏。缺少原始ID时报告限制，不自动相信provider中的每条pair独立。

划分先固定，再做增强、扰动、标定。CAL可选择训练超参数和决策阈值；DEV用于完整探索报告；官方FINAL只在明确freeze后一次运行。外部预训练权重的潜在曝光单列，不能称绝对干净。

## 5. 统计与结果

固定critic的图像/场景cluster区间只覆盖评价抽样，不覆盖所有训练误差。多个seed和多个场景的变异分开；不要把同图数万patch当独立n。

缺失、失败、不可获取写为状态，不用0代替。原始S/J估值、任务损失、几何误差、概率风险、成本不得混列同一单位。不同P/Q的J不直接跨表比高低。

区间含0写“差值区间含0”，不是等效；实用非劣margin需预先根据任务意义定义，不作为录用会议的定理。多对照/事后子组标明探索性。

## 6. 创新与归因

阶段报告前半写结果，后半写新增内容候选。必须列：RPC/RuLSIF或标准Brier结构已覆盖什么；本轮新对象是什么；新算法步骤是什么；哪个外部指标实际使用了估计；什么仍仅是已有方法换场景。

若匹配Logistic与VCS同样好，不删它、不换不平衡先验制造标定差。若核弱但神经都相近，归因于学习型函数类的证据优先，不能声称二次损失独占。

## 7. 本地交付包的验证含义

`tests/`和`validation/`检查参考数学与数据边界约定；不代表完成自然图像配准、音视频训练、服务器性能复测或新颖性排他证明。服务器自然runner由实际代码接入实现，所有建议CLI不得在未实现前写成已可运行。
