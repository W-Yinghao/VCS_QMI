# V7 v1 → v2：明确的增量

## 1. 没有改变的内容
原始混合参考 S/J、语义元素事件、soft 投票、先验修正、prompt-only 分解、E/O/H 三种输出的定义、提示级划分、GenAI-Rank 官方 N=3/N=9 规则均保留。N0/M0/M1/M2 名称及 12 个完整训练单元保留，已启动者不重跑。理论归属仍明确平衡 RPC、相对密度比及正规评分规则的关系。[F01,F02,T01]

## 2. 实质改变
| v1 | v2 |
|---|---|
| H1 首先问 M2 是否赢 M1 | 首先问相对传统估计路线、非 CS 工具和公开任务方法的价值 |
| K0 只有笼统 RFF / relative least squares | 拆为原生 CS-KDE、同目标 KDE、RuLSIF、核平方回归；每条给目标、读数、带宽、成本规则 |
| 非 CS MI 方法主要留在背景 | 进入正式证据覆盖表；MINE/DV、NWJ、InfoNCE、SMILE 不可因 Logistic 接近而撤掉 |
| V7 应用主检验包含 M1 | 主应用确认比较针对 FGA、VQAScore、TIFA、DSG；M1 作为独立归因家族，完整报告 |
| 新文档可能导致重复接入 | 复用最新 `data_fetch.py` 中的 V7 数据项，登记更精确的 GenAI-Rank 入口 |
| 只提“核方法可用于估计子实验” | 增加共同特征的 15 个主拟合单元，核与 KL 样本级读数可接相同选图；不能据此替代完整训练 |

## 3. 新编号不改旧编号
新增任务使用 `V7X-*`：X00 接入增量、X10 旧估计器证据覆盖、X11 传统 CS 数学/代码、X12 非 CS 原生面板、X20 共同特征接入、X21 共同特征拟合、X30 外部系统、X40 统一报告。服务器若已有编号冲突，附映射表而非覆盖。

## 4. 旧结论如何保留
不把过去开发集的正结果升级为独立确认；不把历史文档已经撤回的“必须赢JS”“InfoNCE不能排序”“所有CS只是同一数值”“核计算零成本”等说法写回。旧估计器线先检查后续修复产物，不能拿 10月10日的 bug 清单假定现在仍有 bug。[F02]

## 5. 与新提交的关系

主要完整训练仍为 12；X21 增加的是 4 个神经拟合路线×3 初始化 + 3 个确定性核拟合 = 15 个共同特征实验，不是15个大模型预训练。核的调参与特征提取需计时。X10/X12 的新计算数量取决于真实缺失项，不能宣称所有外部基准已经存在，也不要求重跑完整历史套件。
