# V7完整应用：公开方法与直接竞争

## 1. 主对手不再是M1
主表首先回答：相同prompt、相同generator、相同N=9候选，谁选出的图像具有更高人工对齐H？正式外部对手为FGA-BLIP2、VQAScore、TIFA、DSG。PN-VQA是直接相关的分解式问答参照。简单CLIPScore/随机/先验只作底线，不承担“战胜已有方法”的主张。[P01–P05]

| ID | 方法 | 执行要求 | 结果所代表的比较 |
|---|---|---|---|
| B0 | 发布FGA-BLIP2 | 原生整体score；记录checkpoint是否见过本地留出 | 发布系统；本地N0重训另列 |
| B1 | 原生强VQAScore | CLIP-FlanT5-XXL及锁定legacy环境；不能拿弱宿主代替 | 正式任务基线 |
| B4T | TIFA | 官方问答/过滤/聚合；所有候选使用同一prompt清单 | 不同推理结构的外部方法 |
| B4D | DSG | 保留原子问题依赖与图结构聚合 | 语义分解的强对照 |
| B3 | PN-VQA | 正反提问，成本含所有问题 | 对语义支持的直接参照 |
| B2 | 现代same-host VQAScore | 宿主和模板单独锁定 | 宿主升级影响，不混为原论文复现 |
| B5/B6 | HPSv3 / VisionReward | 原生公开权重与维度，至少完成可运行性核对 | 偏好系统参考，不直接评价Bernoulli校准 |
| B7/B8 | DynEval / DEPICT | 保留v1核验状态，接入时查代码权重；无法得则列原因 | 新方法覆盖，不虚构结果 |

B4T/B4D替代旧B4合并名称：代码/模板/结果分别记录，不把两种算法合成一行“DSG/TIFA”。免费/本地替代官方付费LLM时标为复现适配，不能称完全原生；额外API需授权。

## 2. 系统表和匹配表都保留
系统表允许不同主干、原生数据与计算，但列明资源/训练暴露；不能解释为纯损失因果。匹配表使用共同输入、训练样本、可训练模块和辅助项，N0/M0/M1/M2保持原12单元。只有系统表没有匹配表，可能把主干优势归给损失；只有匹配表没有系统表，则无法证明任务进步。

## 3. 不人为弱化基线
复现不一致先检查权重、输入分辨率、文本截断、question模板、概率读取和解析，保留修正前后。原生方法使用其强且公开的推荐设置；不要求它们全部使用我们的prompt分解才能进入主表。共同解析可以作为额外组件对照。

发布FGA的local-holdout暴露不能用来否定本地重训的公平性；同样不能反过来在本地未见数据表中把发布权重当成同FIT训练。GenAI-Rank的候选池对所有方法完全相同，生成成本不因模型score改变。

## 4. 主应用的比较家族
v2预设主应用家族为M2-E vs {B0-FGA,B1-VQAScore,B4T-TIFA,B4D-DSG}×{DALLE_3,SDXL_Base}，共8个对比。以prompt重采样、跨生成器保留同prompt关联，报告效应量、95%CI与Holm校正。M2-E vs M1-E的2个对比移到独立归因家族，完整展示但不决定是否运行外部方法。

这是比较地位调整，不是撤掉不利结果。若任一主方法不可执行，先公开登记原因及新的冻结家族；如标签已打开则不再重命名“事前主检验”。也不能因为删掉较强方法使得“领先”更容易就改任务主张。

## 5. 真正可用的展示
固定N=1/3/9，官方N3分组不改。每个方法输出同组候选的分数、选择、元素覆盖和实际时间。案例从固定prompt hash分层抽取，含输/平/赢；模型自己的元素概率与人工H用不同标记。发布会式demo建立在完整benchmark上，不人为挑图或把被选结果替换为别的候选。
